plan.html Corrections (v01.002)

  1. Posting ID column is a <th>, not <td>. plan.html said "the posting ID is the text content of the first td". The rendered DOM has <th scope="row"> for the first column. Corrected to: use input[name="dataViewerSelection"].value (numeric string). Fallback: checkbox id matches /^resultRow_(\d+)$/.
  2. Vue template attributes stripped from rendered DOM. plan.html said to use col-key="Id" and :is-id="true" as selectors. These are Vue template props consumed by DataViewer and are absent in the rendered HTML. Removed from spec.
  3. Table selector added. plan.html did not specify how to uniquely identify the jobs table. Added: #dataViewerPlaceholder table.data-viewer-table (the data-viewer-table class is unique to this table on the page).
  4. Action tokens are object-literal values, not var declarations. plan.html said "embedded as string literals... by searching for the function or variable name". The actual pattern is always an object property value (e.g. action: '_-_-...' inside a $.post call). Updated extraction language and provided concrete regexes in both plan.html and exampleWW-compact.html §4.
  5. getPostingOverview returns an HTML string, not JSON. plan.html implied JSON. The function has no explicit dataType on its $.post call, so jQuery returns the raw server response — an HTML string. Must use DOMParser + .textContent to extract plain text before sending to Gemini.
  6. Folder trigger: bare form, not .$data form. plan.html said dataViewerApp.$data.jobFolderEditSidebar = true. The page itself uses dataViewerApp.jobFolderEditSidebar = true (bare, no .$data) for single-row actions. Both work in Vue 3; corrected to bare form.
  7. Vue 3.5.13 IS loaded by the page. plan.html said "NOT a plain Vue 3 SPA" — true, but implied Vue was not present. Vue 3.5.13 is loaded globally as the underlying framework for DataViewer. The extension must not ship its own copy of Vue.

v01.007 — Background worker / Gemini client (2026-05-20)

Network errors abort immediately; only 429s are retried
A network-level fetch failure (DNS, timeout, offline) returns immediately with an error rather than retrying. Retries are reserved for 429 rate-limit responses, which are transient by nature. Non-429 HTTP errors (4xx/5xx) also abort immediately since retrying them is unlikely to help.
JSON parse failure returns the first 100 chars of raw output in the error
Gemini sometimes returns unexpected formats. Including the raw prefix in the error message makes it diagnosable without having to instrument the service worker.

v01.006 — Settings popup (2026-05-20)

Popup makes Gemini test calls directly, not via background.js
The Test API Key button fetches the Gemini endpoint from popup.js rather than routing through background.js. Both contexts have host_permissions for generativelanguage.googleapis.com, so this works and avoids unnecessary message passing for a one-off UI action.
Status element uses CSS classes (ok / err) for color, not inline styles
Keeps popup.js free of style concerns. The classes are defined in popup.html's style block and toggled by setting el('status').className.
