Key v01 architectural decisions to preserve

  • page-bridge.js runs in page context to access dataViewerApp, getPostingOverview, action tokens. Content script ↔ page bridge via postMessage with reqId namespacing.
  • Bridge bypasses getPostingOverview() and hits /myAccount/co-op/full/jobs.htm directly with cached tokens — kills the overlay flicker during scans. Don't revert this.
  • MutationObserver on the <table> (not <tbody>) with rAF-debounced wipe+reinject of badges — DataViewer reuses <tr> elements on page change, in-place badges would leak otherwise.
  • WW pagination puts active / disabled / aria-label on the inner <a class="pagination__link">, not the <li>. scrollToRow's helpers operate on the <a> directly.
  • Pagination anchors are <a href="javascript:void(0);"> — use dispatchEvent(new MouseEvent('click', …)) not .click() or CSP fires on the javascript: URL.
  • background.js validates Gemini response shape (score 1–10, verdict ∈ {Apply, Consider, Skip}, reason non-empty); returns structured {ok, code, error} with code ∈ {NETWORK, RATE_LIMIT, HTTP, PARSE, SHAPE}.
  • Gemini 2.5 Flash thinking mode is disabled (thinkingConfig: { thinkingBudget: 0 }) — thinking tokens otherwise eat the maxOutputTokens budget.

v02.005 — Context caching + responseSchema [DONE]

  • responseSchema: In src/background.js, drop the "Respond with ONLY a JSON object…" prose and field bullets from the prompt. Add responseMimeType: 'application/json' and responseSchema (type object, properties score/verdict/reason with integer/enum/string constraints) to generationConfig. Remove the markdown-fence stripping on the raw response. Keep the existing validate() check — schema doesn't guarantee semantic validity.
  • Cache create: In src/content.js, add a module-level let cacheName = null. At the start of scanAllJobs(), after loading settings, POST to /v1beta/cachedContents with the system instruction + profile parts and ttl: "1800s". Store the returned name in cacheName. On failure, log a warning and leave cacheName null (fall through to inline).
  • Per-call use: Thread cacheName through chrome.runtime.sendMessage to scoreJob in src/background.js. When cachedContent is present in the message, switch the generateContent body to include cachedContent and send only the job-description part as the user turn. When absent, fall back to the current full inline body — no behavior change for callers without it.
  • Cache delete: In the finally block of scanAllJobs(), best-effort DELETE /v1beta/{cacheName} if set. TTL handles the case if delete fails. Reset cacheName = null.
  • Touches: src/background.js, src/content.js.
  • Verify: token log shows cachedContentTokenCount equal to profile size; promptTokenCount is lower than uncached baseline. Fallback: force cache creation to fail and confirm scan still completes at full token cost.

v02.016 — light/dark theme + cumulative token usage [DONE]

  • Theme toggle: Settings nav tab in options.html with Dark/Light pill. Storage key theme — 'dark' (default) or 'light'.
  • Light palette from stitch_waterlooworks_ai_optimizer/stealth_light/DESIGN.md; dark is Stealth Obsidian (unchanged).
  • src/sidebar.css fully converted to CSS vars: --s-* on #ww-ext-sidebar for sidebar internals; --ww-* on :root for badges and row highlight (must reach elements outside the sidebar). :root.ww-light handles the toggle button and badge tooltip via descendant selectors.
  • src/content.js — applyThemeToContent() toggles .ww-light on document.documentElement and #ww-ext-sidebar; chrome.storage.onChanged keeps the WW page in sync when settings tab is open.
  • Token usage: Cumulative input/output/cached token counter displayed on the API tab. Counter persists in storage key tokenUsage: {input, cached, output}; Reset Counter button zeros it.
  • Tokens accumulated in src/background.js (scoring) and src/options.js (PDF extraction) — both call sites covered. Display updates live via chrome.storage.onChanged.
  • Touches: options.html, src/options.js, src/background.js, src/sidebar.css, src/content.js.
