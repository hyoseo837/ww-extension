v8.16 — Single-job scan by posting ID

Goal

Let the user scan one specific posting by its id, instead of the whole table — the cost-conscious "score just this one" case (owner call, 2026-06-16). Per ADR 0053 the two requested surfaces are sequenced: the sidebar posting-ID input ships now (it reuses the batch path verbatim); the detail-page "Scan this job" button is deferred until a posting-detail DOM capture exists, because this project builds WW integration against verified captures, never guesses.

  1. Sidebar "Scan one job" input (v8.16.1) — under the "Scan All Jobs" button, a numeric input + "Scan" button. On submit (click or Enter):
    • Sanitise to digits; empty → a progress-line error, no spend.
    • If the id is already scored, reveal it — show "Already scored: N/20 (Verdict)" in the progress line and scrollToRow(id) (best-effort; off-page ids have no row) — no credit charge.
    • Otherwise confirm the 1-credit cost via the existing confirmScan(1, balance), then runScan([id]) — the audited batch loop with a one-element list. Off-page / cross-board ids already work: bulk scan scores off-page postings today, with the title falling back to the fetched heading or #id (v8.14).
    • Reuse withScanButton (shared Stop/▮ state), so a single scan is stoppable and styled like any scan. Guard against launching while a scan is already running.
    An invalid / nonexistent id rides the existing failure path (fetch error → counted, offered for retry) — no special handling.
  2. Detail-page "Scan this job" button (v8.16.2 — deferred) — blocked on a saved snapshot of a WaterlooWorks posting-detail view (DOM + URL), which the repo does not have. Tracked, not built this phase. See ADR 0053 "Consequences".

Verify

  • node --check passes on every touched ext/src/ file (no build step).
  • Owner manual pass (live WW): load ext/ unpacked on a jobs board. Enter an unscored posting id (one on the current page, then one from another page / the other board) → confirm dialog shows 1-scan cost → it scores and the card appears in the list with the right title (or #id when off-page). Enter an already-scored id → it reveals the existing score with no confirm and no credit change (balance unchanged). Enter junk / empty → a friendly error, no spend. Stop works mid-scan.
