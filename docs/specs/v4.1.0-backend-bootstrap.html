Spec v4.1.0 — Backend bootstrap

Goal

Stand up the backend in server/ with the minimum viable shape: pyproject.toml at v4.1.0, FastAPI app with feature-grouped folder skeleton (auth/, scoring/, billing/, core/), a /health endpoint, a working Dockerfile, deployment to DigitalOcean App Platform, and a Supabase project configured with Google OAuth. package.sh updated to exclude server/ from the Web Store zip — this packaging boundary replaces the repo split as the visibility mechanism (see ADR 0010). No client-side code changes — extension wiring follows in v4.2.

Stack and platform are fixed by ADRs: 0007 (DO App Platform), 0008 (Supabase auth + DB), 0009 (FastAPI), 0011 (uv). Repo layout fixed by 0010 (monorepo).

Files

Added (server/)

server/pyproject.toml
Project metadata, version 4.1.0 (syncs with root manifest.json), dependencies (fastapi, uvicorn[standard]). Uses uv per ADR 0011; hatchling build backend so the project is installable into the venv (required for importlib.metadata.version in /health).
server/uv.lock
uv-generated lockfile, committed. Dockerfile uses uv sync --frozen to install from it.
server/Dockerfile
Multi-stage build: deps install, then thin runtime image. Runs uvicorn app.main:app --host 0.0.0.0 --port $PORT.
server/.do/app.yaml (or dashboard-managed)
DO App Platform spec. Region selection recorded here — match Supabase region.
server/.env.example
Documents required env vars: SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, SUPABASE_JWT_SECRET (or JWKS URL).
server/app/main.py
FastAPI app object. Mounts feature routers.
server/app/core/config.py
Pydantic Settings — env loading.
server/app/core/health.py
GET /health handler. Returns JSON with service name + a build/commit identifier.
server/app/auth/__init__.py, scoring/__init__.py, billing/__init__.py, core/__init__.py
Empty package markers establishing the feature-grouped layout. Real routers land in later phases.

Changed

package.sh
Add a comment explaining server/ exclusion. The script uses an allowlist (only listed files are zipped), so server/ is already excluded by construction. The comment makes the load-bearing intent explicit so a future maintainer doesn't add server/ to the allowlist.
.gitignore
Add Python entries: server/__pycache__/, server/.venv/, server/.env, server/*.egg-info/, server/.pytest_cache/, server/.ruff_cache/, server/.mypy_cache/.
docs/architecture.html
Replace the v4.1-not-yet-built placeholder backend section with the deployed stack: FastAPI in server/, DO App Platform, Supabase (auth + Postgres), Stripe (deferred to v4.5). Record the deployed URL.
docs/reference/api.html
Replace the placeholder body with the real authoritative contract: GET /health spec (request, response, status codes). Anticipated endpoints list stays as a forward reference for v4.2+.
manifest.json
Bump version to 4.1.0.

External setup (not files)

  • Supabase project created; Google OAuth provider enabled; callback URL configured; project keys captured in DO App Platform env.
  • DO App Platform app created, pointed at this repo's server/ sub-path, env vars set.

Verify

  1. Deployed backend URL responds 200 OK on GET /health with a JSON body containing the service name and a build/commit identifier.
  2. Supabase project's Google OAuth provider is configured; a manual sign-in via the Supabase dashboard's test flow returns a valid session JWT.
  3. server/app/ matches the feature-grouped layout from ADR 0009.
  4. server/pyproject.toml version equals 4.1.0; manifest.json version equals 4.1.0; commit message starts with v4.1.0.
  5. ./package.sh produces a zip with no server/ entries. Verify with unzip -l.
  6. docs/reference/api.html documents GET /health with the actual response shape.
  7. docs/architecture.html's backend section names the stack, deploy target, and deployed URL — no remaining "TBD" markers in that section.

Notes

  • Region selection (DO + Supabase) is a load-bearing call for cross-vendor latency — decide and document in architecture.html at phase start.
  • Dependency manager: uv, locked in ADR 0011.
  • Region pair: DO tor1 + Supabase ca-central-1 (both in Canada; lowest latency for UWaterloo users). Decided at v4.1 phase start.
  • DO App Platform deploys from the server/ sub-path of this repo's master branch. Configure the source directory in the App Platform spec.
  • This is the first phase that ships executable backend code; before this, all v4 work was docs. Pre-deploy, run the FastAPI app locally via docker run to confirm /health works.
