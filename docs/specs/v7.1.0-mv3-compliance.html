v7.1.0 — MV3 / Web Store compliance

Goal

Make the extension unambiguously Manifest-V3 / Web-Store compliant so it can be resubmitted. Two concrete changes, both pure compliance — no redesign:

  1. Self-host fonts. Remove the remote Google Fonts <link>s from options.html and welcome.html — the only remote resource left in a shipped page — and serve the fonts from local woff2 files. This is the standing rule from ADR 0030.
  2. Fix a packaging bug. welcome.html is opened by background.js (first-run + action) and options.js via chrome.runtime.getURL, but it is not in the package.sh allowlist. It works in the unpacked dev load (all files present) but 404s in the published build — visible to a reviewer on install. Add it (and the fonts) to the allowlist.

Context for the resubmission: the rejected 0.1.0 artifact was the old v03 public build (manifest predated strict versioning), not the current code — see ADR 0030. The audit confirmed no remote JS/Wasm in ext/; fonts are the only fix needed on the code side.

Files

Added

  • ext/fonts/ — vendored woff2 files: Hanken Grotesk (600, 700), Inter (400, 500), JetBrains Mono (400, 600). The union of what options.html and welcome.html use.
  • ext/src/fonts.css — local @font-face declarations pointing at ext/fonts/, linked by both pages.

Changed

  • ext/options.html — drop the three Google Fonts <link>s (2 preconnect + 1 stylesheet); link src/fonts.css instead.
  • ext/welcome.html — same swap (uses Hanken Grotesk + Inter).
  • package.sh — add welcome.html and fonts/ to the allowlist. (src/fonts.css is already covered by the existing src/ entry.)
  • ext/manifest.json — version 7.0.0 → 7.1.0.

Not changed (deferred)

  • welcome.html content/redesign — staying functionally as-is. The "thin launcher" rework (big Set up your profile → button to the web app; detailed how-to stays in the sidebar) belongs to the later redesign phase, not here.
  • The design/ export keeps its CDN/remote links — it never ships (not in the allowlist).

Verify

  1. grep -rn "fonts.googleapis.com\|fonts.gstatic.com" ext/options.html ext/welcome.html → no matches.
  2. ./package.sh builds; unzip -l on the result lists welcome.html and the fonts/*.woff2 files.
  3. Load ext/ unpacked: the options and welcome pages render with the correct fonts and make no network request to fonts.googleapis.com / fonts.gstatic.com (check DevTools Network).
  4. First-run (or the options-page "open welcome" path) opens welcome.html with no 404 — and would not 404 from the packaged zip either (file is in the allowlist).
  5. grep version ext/manifest.json → "7.1.0".

Notes

Font weights to vendor, by page:

  • welcome.html: Hanken Grotesk 600/700, Inter 400/500.
  • options.html: the above + JetBrains Mono 400/600.

A single shared src/fonts.css declaring all six faces (both pages link it) is simpler than per-page font CSS and costs nothing — unused faces aren't fetched. Fonts are OFL-licensed; bundling is permitted.
