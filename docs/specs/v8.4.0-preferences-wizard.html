v8.4.0 — Preferences redesign: required setup wizard + simplified editor

Goal

Replace the hard-to-understand Match preferences UX with the two-surface model of ADR 0040: a required plain-language setup wizard for first-run capture, and a simplified single-page editor for later changes. Scope confirmed by the owner 2026-06-10 ("simplified single page, with guided wizard; make the wizard essential to use this service"). The match_criteria jsonb schema is unchanged; scorer and extension untouched.

Wizard — /preferences/setup

Renders outside the app shell (focused, like /admin). One question per step, Back/Next, progress indicator. Steps:

  1. Work authorization — required radio (citizen / PR / international / other). The only non-skippable step; it is an eligibility gate for scoring.
  2. Locations — chip input ("Where do you want to work?") + importance (Nice to have / Important / Must-have → weight). Skippable.
  3. Work mode — preset chips (Remote / Hybrid / On-site) + importance. Skippable.
  4. Timing — target term (text, e.g. "Fall 2026") and term length (preset chips 4-month / 8-month) + one shared importance. Skippable.
  5. Anything else — free textarea for dealbreakers and context, saved to the existing preferences notes field. Skippable.

Finish saves via PUT /profile with wizard_completed_at = now inside match_criteria, then navigates to /account. Languages and the avoid/never tiers are deliberately not in the wizard — they live on the editor page.

Simplified editor — /preferences (rebuild)

  • Same sections, plain vocabulary: importance select labeled Nice to have / Important / Must-have; tiers shown as Ideal / Would rather not / Never (acceptable dropped from UI, preserved in data).
  • Work mode uses preset chips (Remote / Hybrid / On-site) instead of free text; other criteria keep the tag input.
  • "Would rather not" / "Never" stay collapsed behind a clearly named "Fine-tune (avoid / never)" toggle per criterion.
  • Header links "Re-run setup wizard" → /preferences/setup.
  • Eligibility select, notes textarea, and the fixed save bar stay.

Gate + onboarding integration

  • Gate: the signed-in app shell fetches the profile once; if setup is incomplete (wizard_completed_at unset and no work authorization and no preferred values anywhere), every shell route redirects to /preferences/setup. Legal pages and /admin stay reachable.
  • Checklist: the dashboard getting-started card (v8.1.2) gains step "Set your match preferences" between profile and first scan (4 steps total); done = the same derivation as the gate. The card's retire condition includes it.
  • /getting-started page mentions preferences setup in its walkthrough.

Verify

  • New account (or account with empty criteria): signing in lands on the wizard; completing it lands on /account with the preferences checklist step checked; criteria visible on /preferences.
  • Existing account with criteria: no redirect, page works as editor; values round-trip through PUT /profile unchanged (including untouched acceptable data).
  • GET /profile returns wizard_completed_at after wizard completion (field survives Pydantic).
  • Web build + tsc clean.

Notes

  • Freeform-dealbreakers land in preferences notes — the scorer already weighs that field; no prompt change.
  • If web-side funnelling proves leaky (users scanning with empty criteria anyway), the server-enforced gate option in ADR 0040 is the follow-up.
