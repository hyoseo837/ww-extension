v7.5.0 — UWaterloo (Microsoft Entra) sign-in

Goal

Replace Google OAuth with Microsoft Entra (UWaterloo) sign-in across the web app and the extension, per ADR 0036, so only UWaterloo students can create accounts (anti-abuse). Status: planned — the spike (2026-06-05) passed and the decision is made, but code is deferred; this spec is the implementation plan.

Prerequisites (dashboard — owner)

  1. Entra app registration (done in spike): multitenant; redirect URI https://bumrzedwwfhbxlttwboh.supabase.co/auth/v1/callback; client ID + secret; email optional claim added (Token configuration) so Supabase receives the email.
  2. Supabase → Auth → Providers: enable Azure (client ID/secret, tenant URL https://login.microsoftonline.com/common); disable Google.
  3. Before flipping: confirm no real paying users exist (Supabase → Users + credit ledger). Existing Google accounts orphan their credits (ADR 0036).

Code changes (touchpoints found 2026-06-05)

Web app

  • web/src/supabase.ts — signInWithGoogle → signInWithMicrosoft: provider: "azure", options.scopes: "email" (so the email claim is requested).
  • web/src/pages/Landing.tsx — both sign-in buttons (hero + pricing "Sign in to buy") label "Sign in with Google" → "Sign in with your UWaterloo account"; replace GoogleMark with a Microsoft mark; update the import.

Extension

  • ext/src/options.js — the authUrl provider=google → provider=azure (add &scopes=email); status text "Opening Google sign-in…".
  • ext/options.html — the #signIn button "Sign in with Google" and the Account-card sign-in blurb.
  • ext/src/content.js — sidebar empty-state guide "Sign in with Google in Settings" → "Sign in with your UWaterloo account".
  • (welcome.html already says generic "Sign in under Settings" — no change needed.)

Legal (sign-in references only — keep Gemini/Google API mentions)

  • web/src/pages/legal/Privacy.tsx — the account-identity / "sign-in is through Google" / "no password" lines → Microsoft/UWaterloo. Leave the Gemini-API "Google" references (lines about the paid Gemini tier) — that processor is unchanged.
  • web/src/pages/legal/Terms.tsx — "You need a Google account to sign in" → UWaterloo account. Leave the "depends on Google, Stripe, Supabase…" dependency line (Google still provides Gemini).

Optional follow-up — enforce the uwaterloo.ca domain

common tenant accepts any Microsoft org / personal account. To hard-restrict to UWaterloo, reject sessions whose email domain / tenant isn't UWaterloo (a Supabase auth hook or a server-side check on the JWT). Decide whether this is needed or whether "must have an @uwaterloo.ca to be useful anyway" is enough.

Verify (at implementation)

  1. Web + extension: signing in with @uwaterloo.ca completes end-to-end; the new user row carries the email; Google is no longer offered anywhere.
  2. If domain-enforced: a non-uwaterloo Microsoft account is rejected.
  3. grep -rni "google" web/src ext/src ext/*.html returns only the intended Gemini-API references + the chromewebstore link — no sign-in copy.

Notes

  • Server change is unlikely (auth is Supabase-side); if any server/ file changes (e.g. a domain-enforcement check), bump pyproject.toml (ADR 0010).
  • Migration of any real existing Google user's credits is manual (ADR 0036) — handle before disabling Google if such users exist.
