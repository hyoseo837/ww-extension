v8.1.0 — New-user onboarding guidance

Goal

Tell a new user what to do. Today the web app sells the product (landing) and, after sign-in, drops the user on the dashboard with 100 free credits and no next step. The three actions that produce the first "aha" — install the extension, set up your profile, run a scan — are never surfaced. This phase adds clear getting-started guidance in three places, the dashboard one being a smart checklist that tracks progress.

Opened from a direct user request (2026-06-06), with scope confirmed by the owner: all three surfaces below, and a progress-tracking (not static) dashboard checklist. This is the first v8 feature thread, so it opens the v8.1.x minor line; earlier v8.0.x was doc/maintenance only.

Surfaces

  1. Landing "How it works" (public, logged-out). A three-step section — Install · Set up your profile · Scan — placed between the existing Features and Pricing sections, so a visitor understands the flow before signing in. Static, no state.
  2. Dashboard getting-started checklist (signed-in). A card at the top of /account for new users with the same three steps, each auto-checked as it's completed, each with an action button. Hides once the user is fully set up. This is the core of the phase.
  3. Dedicated Getting Started page (signed-in, /getting-started). A fuller walkthrough — the three steps expanded with detail and a short FAQ — linked from the dashboard card and the nav. The durable "how do I use this?" reference.

Checklist state model

Per ADR 0038, all state is derived web-side from data the dashboard already fetches; no extension or backend change.

StepDone whenAction button
1 — Install the extension hasScanned (a scan proves install), or a manual ack stored in localStorage.ww_onboarding_ext_installed Open Chrome Web Store (CHROME_STORE_URL)
2 — Set up your profile cvReady from GET /profile (profile_json.summary / experience / legacy cv_text) Go to /profile
3 — Run your first scan any scan_debit entry in GET /credits/history Open the WaterlooWorks jobs list (new tab)

The card is shown while the user is not fully set up, and hidden once they are (profile ready and at least one scan). It is a first-run aid that retires itself — never a persistent nag.

Out of scope

  • No precise extension-install detection (would need an extension change; see ADR 0038 consequences).
  • No backend changes, no new endpoints, no schema changes.
  • No interactive product tour / tooltips — just the three surfaces.

Slices

Each is its own v8.x commit (ADR 0002); all are web-only, so each bumps ext/manifest.json but not server/pyproject.toml.

  • v8.1.0 — docs: this spec + ADR 0038.
  • v8.1.1 — web: Landing "How it works" section.
  • v8.1.2 — web: dashboard getting-started checklist (smart, self-retiring).
  • v8.1.3 — web: /getting-started page + nav/dashboard link.

Done when

  • A logged-out visitor sees a clear 3-step "How it works" on the landing.
  • A brand-new signed-in user sees a checklist guiding install → profile → scan, with steps checking off as they're completed, and the card disappearing once set up.
  • A /getting-started page exists with the expanded steps, reachable from the dashboard and nav.
