v8.7.0 — Extension on the Employer-Student Direct board

Goal

The extension currently activates only on the Full-Cycle Service jobs page. Make it work identically on https://waterlooworks.uwaterloo.ca/myAccount/co-op/direct/jobs.htm (Employer-Student Direct), the second WW job board.

Evidence

Owner-captured rendered DOM of the Direct board (docs/reference/ww-dom-direct-full.html, 2026-06-10) confirms full structural parity with the Full-Cycle page: identical results-table markup (tr.table__row--body, dataViewerSelection inputs, td.table__value column order), identical pagination, the same inline getPostingOverview / onSelectAll functions with the same action: token shape (the page-bridge token regexes match unchanged), and the same dataViewerApp Vue root with sidebarPostingIds / jobFolderEditSidebar for folder saves. The single difference: the page's AJAX posts target its own path, /myAccount/co-op/direct/jobs.htm.

Change

  • ext/manifest.json — add the Direct URL pattern to the content-script matches (host permission already covers waterlooworks.uwaterloo.ca/*).
  • ext/src/content.js — the selectAll list fetch posts to location.pathname instead of the hardcoded Full-Cycle path.
  • ext/src/page-bridge.js — fetchOverview posts to location.pathname likewise.
  • docs/reference/ww-dom.html — note the Direct board's parity and the posts-to-own-path rule.

The score cache (ww_scores, keyed by posting id) is shared across both boards by design — posting ids are board-global, so a job scored on one board shows its badge on the other.

Out of scope

No backend or web-app change. No new ADR — no decision beyond applying the existing architecture to a second URL.
