v6.11.0 — Web UI refinements (nav, credit display, preferences input)

Goal

Three user-requested UI fixes to the web app, sliced into two commits. No backend or behavior change.

v6.11.0 — nav cleanup + credit display

  • Drop "Credits" from the nav (Layout.tsx, desktop sidebar + mobile top bar). The sidebar's bottom Buy Credits button already routes to /buy, so the nav item was a redundant duplicate. /buy route is unchanged.
  • Readable credit numbers (format.ts + the balance displays). The balance is a NUMERIC(14,6), so raw it renders like 4559.289506 — noise. New fmtBalance(n) (thousands-separated, ≤2 decimals) and creditUnit(n) ("credit"/"credits"). Applied to the dashboard balance card (number + a "credits" unit), the Billing balance, and the Admin user table / inspect modal / grant confirmation.

v6.11.1 — preferences input layout

  • Preferences.tsx (TagInput / CriterionEditor): the text input and the added-keyword chips move to separate lines (input row on top, chips below) instead of sharing one wrapping box. The weight selector moves out of "More options" and onto the same line as the input box (always visible). "More options" now reveals only the acceptable / avoid / excluded tiers.

Verify

  1. cd web && npm run build clean.
  2. Sidebar (desktop + mobile) shows Dashboard / History / Profile / Preferences — no "Credits"; Buy Credits still reachable from the bottom button and the dashboard.
  3. Balances read like "142 credits" / "4,559.29" — never 6-decimal noise — on the dashboard, Billing, and Admin.
  4. On Preferences, each criterion shows an input box with the weight selector beside it, the chips on the line below, and "More options" toggles only the other tiers.

Notes

fmtCredits (signed deltas in the history list) already capped at 2 decimals — unchanged. Stat cards on Admin keep fmtCompact ("128.5k") — that is intentional for big aggregates, distinct from a user's balance.
