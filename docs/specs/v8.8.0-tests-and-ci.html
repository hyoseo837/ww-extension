v8.8 — Server tests + CI + version hygiene

Goal

Give the server a test suite and the repo a CI gate before v8.9 touches the credit flow (ADR 0046, audit findings #1 and #4). Scope is the pure and near-pure server logic — pricing math, verdict bands, result validation, criteria/profile serialization, ledger SQL — plus a GitHub Actions workflow that runs ruff + pytest on server/ and typecheck + build on web/ for every push. Also catches server/pyproject.toml up from its stale 6.11.0 so /health reports the truth again. The extension is explicitly out of scope (no build step, ADR 0026; manual verification stands per ADR 0046).

Files

  • server/pyproject.toml — changed: bump version to match the release commit; add a dev dependency group (pytest, pytest-asyncio, ruff); add [tool.ruff] and [tool.pytest.ini_options] config.
  • server/tests/test_pricing.py — added: token estimation, scan/extract cost estimates, actual_cost against known usage dicts, package table sanity (cad_cents ≤ credits beyond entry tier).
  • server/tests/test_scoring_logic.py — added: verdict_for band edges (6/10/14/17, excluded override), _valid_result accept/reject cases, _format_criteria / build_job_part / build_profile_context serialization (empty inputs emit nothing; supplement marked self-reported; legacy cv_text fallback).
  • server/tests/test_ledger.py — added: DB-backed tests for insert_scan_pending idempotency, balance_after_estimate, grant_purchase replay no-op, and the get_history debit+refund collapse. Runs against a disposable Postgres (CI service container); skipped locally when TEST_DATABASE_URL is unset.
  • server/tests/conftest.py — added: event-loop / pool fixtures, schema setup from server/migrations/ applied in order to the test DB.
  • .github/workflows/ci.yml — added: on push/PR — job 1: ruff check + pytest (with Postgres service) in server/ via uv; job 2: npm ci && tsc --noEmit && vite build in web/.
  • ext/manifest.json — changed: version bumps per commit, as always.

Verify

  • uv run pytest in server/ passes locally (ledger tests skip without TEST_DATABASE_URL, run with it).
  • uv run ruff check . in server/ is clean.
  • The GitHub Actions run on dev is green, including the DB-backed ledger tests against the service container.
  • GET /health on the next production deploy reports the new version (deploy-skew check restored, ADR 0010).
  • No behaviour change anywhere: no production code is modified in this phase except the version string.

Notes

  • Migrations double as the test schema — if applying server/migrations/*.sql in order to a blank Postgres fails, that's a real finding (the production DB was migrated by hand), worth recording when discovered.
  • The ledger tests deliberately encode today's behaviour, including the read-committed balance race (audit #3) — v8.9 then changes the behaviour and flips the test, proving the fix.
