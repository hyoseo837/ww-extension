Spec v5.4.0 — Preserve line breaks in extracted raw documents

Goal

Fix to the v5.1 PDF extraction. The extract prompt copies the grade report, co-op work-history, and cover letter into raw-text fields (grade_report / coop_history / cover_letter) but never tells Gemini to keep the line breaks, so the model flattens them into a single line. That degrades both the options-page display (rendered in a <pre>) and — more importantly — the scan input: a transcript or work-history is far easier for the scorer to read with one course/term per line than as a run-on blob. Make line-break preservation explicit in the extract prompt.

Files

server/app/scoring/gemini.py (changed)
_PROFILE_EXTRACT_PROMPT — instruct Gemini to preserve the original line breaks (newline-separate each transcript/course row, work-term entry, and paragraph; do not flatten). Schema/transport unchanged — JSON strings carry \n natively.
server/pyproject.toml, manifest.json (changed)
Version bump.
