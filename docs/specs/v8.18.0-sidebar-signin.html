v8.18 — Sign in from the sidebar credits field

Goal

Let a signed-out user sign in with UWaterloo straight from the sidebar credits field, instead of only via the options page (whiteboard, owner call 2026-06-16). Per ADR 0055, the Azure/Supabase OAuth flow (chrome.identity.launchWebAuthFlow, unavailable in content scripts) is centralized in the background worker as one signIn message handler that both the options page and the sidebar call. Extension-only; no server/web change.

  1. Centralize the OAuth flow (v8.18.1) — add signIn() + a { type: 'signIn' } handler to background.js: run launchWebAuthFlow, parse tokens + JWT claims, write auth to storage, return { ok, email } | { ok:false, error }. Refactor options.js's sign-in button to send the message and drop its inline copy of the flow (and the now-unused SUPABASE_URL / decodeJwtPayload / post-sign-in refreshBalance ping — the background's storage.onChanged already refreshes the balance on an auth write).
  2. Sidebar credits-field sign-in (v8.18.2) — renderCreditsChip stops hiding the node when signed out; it renders a compact "Sign in" chip-button that sends signIn (disabled → "Signing in…" while the popup is up). On success the background writes auth; the existing core.js storage.onChanged reaction re-renders the chip as the ⚡ balance and ticks the guide's step-1 check. On failure, surface the error on the progress line and restore the button.

Files

  • ext/src/background.js — signIn() + signIn message handler (reuses decodeJwtPayload, SUPABASE_URL).
  • ext/src/options.js — sign-in button → send signIn; remove the inline OAuth flow and its now-dead helpers/constants.
  • ext/src/content/sidebar.js — renderCreditsChip signed-out branch renders the "Sign in" button; a startSignIn() helper sends the message and handles the error path.
  • ext/src/sidebar.css — style the signed-out #ww-ext-credits sign-in button.
  • ext/manifest.json — version bumps.

Verify

  • node --check passes on every touched ext/src/ file.
  • Owner manual pass (live WW): signed out, the sidebar header shows a "Sign in" button instead of the credits chip; clicking it opens the UWaterloo popup; after signing in, the button becomes the ⚡ balance and the guide's step 1 shows ✓ — with no reload. Cancelling the popup restores the button and shows a message. The options-page sign-in still works (same shared handler).

Notes

  • No manifest permission change — identity is already granted and launchWebAuthFlow runs in the service worker.
  • The empty-list guide's "Sign in … in Settings" wording is left as is (Settings still signs in); this phase adds the credits-field path, it doesn't replace the guide.
