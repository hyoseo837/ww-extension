Spec v5.5.0 — Prompts in a distinct module

Goal

Refactor (no behavior change). Move the model-facing prompts and response schemas out of scoring/gemini.py into a new scoring/prompts.py, so the prompts are easy to find and iterate on separately from the Gemini transport / serialization / parsing logic. They stay server-side (like all of server/, excluded from the Web Store zip), so the scoring prompt never ships to end users — the original rationale is unchanged, only the file is.

Files

server/app/scoring/prompts.py (added)
Holds SYSTEM_TEXT + RESPONSE_SCHEMA (scan contract) and PROFILE_EXTRACT_PROMPT + PROFILE_SCHEMA (extract contract). Names made public (dropped the leading underscores) since they're now imported.
server/app/scoring/gemini.py (changed)
Imports the four from prompts; the definitions are removed and the docstring updated. Transport, serialization (build_job_part / build_profile_context), verdict ladder, and validation stay here.
server/pyproject.toml, manifest.json (changed)
Version bump.

Verify

  1. py_compile passes for both files; the four constants import from prompts.
  2. The /scan and /profile/extract request bodies are byte-identical to before (prompts + schemas moved, not changed).
