v8.6.6–v8.6.8 — Scan feedback loop

Goal

Implement ADR 0044: 👍/👎 per scored posting in the extension's score panel, an optional one-line "what was wrong?" on 👎, stored against the exact scan row and reviewed on the admin page. v8.6.0–v8.6.5 were pre-phase maintenance commits; this spec covers the feature slices v8.6.6–v8.6.8.

v8.6.6 — backend

  • server/migrations/0012_scan_feedback.sql — table per ADR 0044 (PK scan_id → scan(id) cascade, user_id, rating check up/down, comment, description_text, created_at/updated_at; RLS select-own, no write policy). Applied manually in the Supabase SQL editor by the owner.
  • server/app/scoring/routes.py — POST /scan/feedback: body {scan_id, rating, comment?, description_text?}. 404 if the scan row isn't the caller's successful kind='scan' row. Upsert; comment trimmed and capped at 500 chars, description_text capped at 6000 (the extension's DESC_CHAR_CAP) and ignored unless rating is down. Returns {"ok": true}.
  • server/app/admin/routes.py + admin/db.py — GET /admin/feedback?limit&offset: recent feedback joined to scan (posting id, title, org, model, stored score/verdict) and user email.
  • docs/reference/api.html — both endpoints added to the contract.
  • server/pyproject.toml — 6.11.0 (new feature).

v8.6.7 — extension

  • ext/src/background.js — scoreJob returns the generated scan_id alongside the result; new sendFeedback message → POST /scan/feedback.
  • ext/src/content.js — cache entries gain scanId (set on scan success) and feedback ('up'/'down', set after a successful send). Sidebar cards with a scanId render 👍/👎 in the actions row; the active vote is highlighted and can be switched. 👎 reveals an optional one-line input + Send; on send the content script re-fetches the posting overview via the page bridge (same extraction as a scan, free) and includes the trimmed description. Entries without scanId (pre-v8.6 cache) show no buttons. Additive cache change — no SCORING_SCHEMA_VERSION bump.
  • ext/src/sidebar.css — feedback button + input styles.

v8.6.8 — web admin + close-out

  • web/src/pages/Admin.tsx — "Scan feedback" section listing recent feedback (rating, email, posting title/org, score/verdict, comment, date; 👎 rows expandable to the stored description).
  • Close-out: spec status → done; whiteboard entry moved to Solved (with owner's permission); privacy-policy data inventory gains the feedback row.

Out of scope

Per ADR 0044: per-user score adjustment, implicit signals, any credit tie, and automated prompt evaluation. The loop closes by hand.
