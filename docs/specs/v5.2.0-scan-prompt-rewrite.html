Spec v5.2.0 — Scan-prompt rewrite + richer scoring output

Goal

Third v5 phase (thread #3) — the scoring-quality payoff. With criteria (#1) and the profile (#2) now structured, rewrite the scan prompt and the output. The prompt gains work-term framing (early-career WaterlooWorks roles of varying duration — 4/8/12-month or multi-term co-ops, and full-time/new-grad postings — judged at the posting's actual level and against the candidate's target-term/length criteria, not a fixed 4-month assumption), explicit 1–20 band definitions, and a reason-before-score (chain-of-thought) output ordering for sharper calibration. The output moves to a 1–20 score, a verdict ladder derived server-side (five score bands plus an Excluded verdict for hard-criteria/eligibility gates), and a structured per-aspect breakdown — the specific criteria/profile points that gained or lost points — surfaced in the sidebar. The output contract is fixed in ADR 0016, with the 1–20 scale and the Excluded verdict revised in ADR 0017.

Scope: the prompt rewrite + the new output, end to end (backend contract through badges/sidebar). Calibration is anchored only — band definitions and work-term framing in the system prompt; no real few-shot yet (a later tuning pass adds few-shot from accumulated live disagreements, ADR 0016). Hard filters (#4) stay separate. The options-page profile/criteria UI is untouched (its redesign is deferred to v6); the in-page sidebar/badge changes here are kept minimal and functional — enough to render the new scale, tiers, and breakdown, not a visual overhaul.

Output contract (ADR 0016, scale + Excluded per ADR 0017)

Model returns score (1–20), reason (2–3 sentence summary), breakdown (array of { point, effect }, effect ∈ plus | minus, may be empty), and excluded (boolean — true on a hard-criteria/eligibility gate). The server derives verdict from excluded then the score: excluded → Excluded; otherwise by band:

Strong Apply
17–20
Apply
14–16
Consider
10–13
Unlikely
6–9
Skip
1–5
Excluded
hard gate fails (work-auth/citizenship/clearance, or a criterion in the candidate's "excluded" tier); model also scores it 1–5

ScanResult returned to the client is { score, verdict, reason, breakdown }.

Verify

  1. A real scan returns a 1–20 score, a non-empty reason, and a breakdown of gain/loss points; the server-derived verdict matches the score's band at each boundary (e.g. 16→Apply, 17→Strong Apply).
  2. A bad model output (score out of range, bad effect) is rejected → 502 + full refund, as today.
  3. After upgrading the extension, previously cached scores are gone (no mixed 1–10 / 1–20 badges); re-scanning a posting produces the new shape.
  4. Badges show score · verdict across all six verdicts with distinct colors (light + dark). The sidebar card shows the breakdown list; the badge tooltip still shows the reason.
  5. Save-to-folder: the score threshold works on the 1–20 scale and the 6 verdict toggles filter correctly.
  6. Calibration sanity: a hard-gate posting (work-auth/citizenship mismatch, or a job in an "excluded" location) lands in Excluded with the gate named in the breakdown and a 1–5 score; a poor-fit-only posting lands in Skip/Unlikely; a strong match lands in Apply/Strong Apply.

Notes

  • Anchored calibration only (decided with the user). Few-shot from real disagreements is a later tuning pass once live v5 scans accumulate; it won't change the ADR 0016 contract.
  • Server-derived verdict keeps score and verdict consistent; the band ladder is one function (ADR 0016).
  • Minimal sidebar/badge work — render the new scale, tiers, and breakdown; no visual overhaul (the in-page and options UI redesign is v6).
  • Clear-on-upgrade via a stored scoring-schema version, not just load-validation (old 1–10 entries would otherwise pass validation and mix scales).
  • Slicing. backend (prompt + schema + contract + verdict ladder) → client (scale/verdict/badge + clear-on-upgrade, then breakdown render + folder filter — may be two sub-versions) → close-out. Z numbers at build time.
