Spec v5.2.0 — Scan-prompt rewrite + richer scoring output

Goal

Third v5 phase (thread #3) — the scoring-quality payoff. With criteria (#1) and the profile (#2) now structured, rewrite the scan prompt and the output. The prompt gains co-op framing (this is a student work-term, not a full-time hire), explicit 1–100 band definitions, and worked verdict anchors. The output moves to a 1–100 score, a 5-tier verdict ladder derived server-side from the score, and a structured per-aspect breakdown — the specific criteria/profile points that gained or lost points — surfaced in the sidebar. The output contract is fixed in ADR 0016.

Scope: the prompt rewrite + the new output, end to end (backend contract through badges/sidebar). Calibration is anchored only — band/co-op framing and worked anchors in the system prompt; no real few-shot yet (a later tuning pass adds few-shot from accumulated live disagreements, ADR 0016). Hard filters (#4) stay separate. The options-page profile/criteria UI is untouched (its redesign is deferred to v6); the in-page sidebar/badge changes here are kept minimal and functional — enough to render the new scale, tiers, and breakdown, not a visual overhaul.

Output contract (ADR 0016)

Model returns score (1–100), reason (2–3 sentence summary), and breakdown (array of { point, effect }, effect ∈ plus | minus, may be empty). The server derives verdict from the score:

Strong Apply
85–100
Apply
70–84
Consider
50–69
Unlikely
30–49
Skip
1–29

ScanResult returned to the client is { score, verdict, reason, breakdown }.

Verify

  1. A real scan returns a 1–100 score, a non-empty reason, and a breakdown of gain/loss points; the server-derived verdict matches the score's band at each boundary (e.g. 84→Apply, 85→Strong Apply).
  2. A bad model output (score out of range, bad effect) is rejected → 502 + full refund, as today.
  3. After upgrading the extension, previously cached scores are gone (no mixed 1–10 / 1–100 badges); re-scanning a posting produces the new shape.
  4. Badges show score · verdict across all five tiers with distinct colors (light + dark). The sidebar card shows the breakdown list; the badge tooltip still shows the reason.
  5. Save-to-folder: the score threshold works on the 1–100 scale and the 5 verdict toggles filter correctly.
  6. Calibration sanity: a clearly-ineligible posting (e.g. work-auth mismatch via #1 criteria) lands in Unlikely/Skip with the mismatch named in the breakdown; a strong match lands in Apply/Strong Apply.

Notes

  • Anchored calibration only (decided with the user). Few-shot from real disagreements is a later tuning pass once live v5 scans accumulate; it won't change the ADR 0016 contract.
  • Server-derived verdict keeps score and verdict consistent; the band ladder is one function (ADR 0016).
  • Minimal sidebar/badge work — render the new scale, tiers, and breakdown; no visual overhaul (the in-page and options UI redesign is v6).
  • Clear-on-upgrade via a stored scoring-schema version, not just load-validation (old 1–10 entries would otherwise pass validation and mix scales).
  • Slicing. backend (prompt + schema + contract + verdict ladder) → client (scale/verdict/badge + clear-on-upgrade, then breakdown render + folder filter — may be two sub-versions) → close-out. Z numbers at build time.
