v8.15 — Pricing refresh

Goal

Refresh the credit packages and the signup bonus per ADR 0052 (owner confirmed 2026-06-16). The price ladder becomes a rounder $5 / $10 / $20 — the $3 entry tier is dropped and a $20 top tier is added — and the signup bonus doubles to 200 credits so it again buys ~100 scans at today's ~2 credits/scan rate (ADR 0048). Amounts only; the bonus-pack model (ADR 0034) is unchanged.

  1. Package table: drop $3, add $20 — the server (billing/payments.py CREDIT_PACKAGES) and web (web/src/packages.ts PACKAGES) tables, which must stay in lockstep, become:
    idcad_centscreditsnote
    credits_525500525$5 — 500 + 25 bonus
    credits_110010001100$10 — 1,000 + 100 bonus
    credits_250020002500$20 — 2,000 + 500 bonus
    credits_525 and credits_1100 keep their ids and values verbatim; only credits_300 leaves and credits_2500 joins. The Buy and Landing pages render PACKAGES dynamically (3-col grid) — no layout change. Keep credits_525 as the popular pick.
  2. Signup bonus 100 → 200 — a new migration (0014_signup_bonus_200.sql) recreates grant_signup_bonus() with bonus_amount := 200, mirroring 0005. The one-per-user partial unique index and the ADR 0029 re-register suppression are untouched; create-or-replace updates the function in place. Only future grants change — no backfill of existing 100-credit bonuses.
