v8.12 — Friend-invitation bonus

Goal

Ship the referral channel decided in ADR 0050 before the September wave: the inviter earns 20 credits when an invited friend's first scan settles. One-sided, attributed by email at onboarding, suppression shared with ADR 0029.

Server

  1. Migration 0013_referral.sql:
    • referral table: invitee_user_id (uuid, PK, references auth.users on delete cascade), inviter_user_id (uuid, not null, references auth.users on delete cascade), created_at. RLS enabled, no user policies (backend service-role writes only, same posture as migration 0011).
    • Extend the credit_ledger_entry.kind check constraint with referral_bonus.
    • Partial unique index on (ref) where kind = 'referral_bonus' — at most one bonus per invitee, ever (the grant's idempotency key, like migration 0004's purchase index).
  2. POST /referral (authenticated) — body {"inviter_email": "..."}, normalized lower/trim. Creates the attribution row. Rejections:
    • 400 — own email (no self-invites);
    • 404 — no account with that email (honest error so a typo is fixable; disclosure trade-off accepted in ADR 0050);
    • 409 — attribution already exists, or the caller already has a scan row (signup-time question only);
    • 403 — caller's email hash is in signup_bonus_block (re-registered identity, ADR 0029 reuse — same SQL hash expression).
  3. GET /me gains referral_eligible: bool — true iff no attribution row, no scans yet, and not suppression-blocked. The wizard uses it to decide whether to show the question.
  4. Grant hook in scan settlement: when a scan settles successfully and a referral row exists for the scanning user, insert the inviter's ledger row (kind='referral_bonus', delta=+20, ref=<invitee user_id>) on conflict do nothing. The partial unique index makes "first scan only" emergent — no first-scan detection code.
  5. /account/export includes the user's referral attribution (both directions: who they named, and that they were named, ids only).

Web

  1. Wizard step — "Who invited you?" (optional, skippable): appended to the preferences-setup wizard (ADR 0040), shown only when /me reports referral_eligible. One email input; submit calls POST /referral; a 404 shows "No account with that email" inline; Skip moves on. Failures never block the wizard.
  2. Invite blurb on /buy: one quiet card — "Invite a friend: when they run their first scan, you get 20 credits (≈ 10 scans). They just enter your email during setup." No links, no codes, nothing to manage.
  3. Share marketing on the landing page and dashboard (owner-requested scope addition, 2026-06-12):
    • Landing — a referral banner between How-it-works and Pricing: invite friends, earn 20 credits per friend who scans. Speaks to both audiences: existing users learn the program exists; invited visitors learn what the "Who invited you?" step is for.
    • Dashboard (/account) — an "Invite a friend" card showing the user's own email (the thing the friend must type) and a copy-to-clipboard share message (app pitch + URL + "put my email in setup") so sharing is one click into any chat.
  4. Credit history label: kindLabel / HistoryList map referral_bonus → "Friend invite bonus" with a fitting icon.
  5. Privacy policy: one added line — attribution (who invited whom) is stored for bonus crediting and deleted with either account.
