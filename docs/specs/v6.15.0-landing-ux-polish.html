v6.15.0 — Landing & UX polish

Goal

The last v6 web pass before the v7 extension work: make pricing visible to logged-out visitors, give the data pages honest loading / error states, and serve a real 404 instead of a silent redirect. Three independent fixes, grouped because each is small.

1. Pricing visible to logged-out users

Today the price tiers live only in Buy.tsx, behind sign-in, so a visitor can't see what scanning costs before committing a Google login. The package list is a hard-coded constant mirroring the server's CREDIT_PACKAGES (payments.py).

  • Extract the tiers into a shared src/packages.ts (single source for both pages; still mirrors the server constant — the comment moves with it).
  • Add a Pricing section to Landing.tsx rendering the same tiers, display-only: the CTA is "Sign in to buy" (checkout needs an authenticated session and a Stripe call), not a live purchase button. Keeps the one-decision landing — sign in — intact while answering "what does it cost?".
  • Buy.tsx imports the shared list instead of its local copy.

2. Real 404

Today the authenticated catch-all * does <Navigate to="/account"> — a stray/mistyped URL silently teleports to the dashboard, hiding the mistake. Add src/pages/NotFound.tsx (a plain 404 card with a link back to the dashboard) and point the authenticated * at it.

Logged-out * stays the landing. The only valid logged-out paths are /, /privacy, /terms; an unknown path there is most often a deep link to an app page the visitor must sign in to reach, so falling back to the landing (which prompts sign-in) is the right call — a 404 would be worse UX. So the real-404 fix targets the authenticated catch-all, where "this page doesn't exist" is unambiguous.

3. Loading / error / empty states

Audit of the data-driven pages — most already handle these; two swallow errors. Scope is just closing those gaps, not a redesign.

  • Profile, Preferences — already show "Loading…" and a load/save error line. No change.
  • HistoryList — already renders "No activity yet." when empty. No change.
  • Account — the history/profile fetches .catch(() => {}) silently. Add a loading flag (so "Recent activity" doesn't flash the empty state before data lands) and an inline error line when the history fetch fails.
  • Billing — the history load swallows errors and shows no loading indicator. Add loading + error states: a loading line on first load, an inline error if it fails.

Kept inline per the minimal-code rule (two pages, a few lines each) rather than introducing a shared status-banner abstraction.
