v6.13.0 — Confirm before spending credits

Goal

Add a confirmation step before any action that spends credits, so a stray click can't burn the user's balance. From the whiteboard ("fixes needed: confirmation button for any credit uses"). Today the Scan All Jobs button (#ww-ext-scan, content.js:795) runs scanAllJobs() immediately and each unscored posting hits /scan, debiting credits with no prompt.

Scope — where credits are actually spent

The only credit-spending action in the product today is the extension's Scan All Jobs batch (each posting scored = one /scan debit). Buying credits is the web app (not a "use"), and re-score is a future whiteboard item. So a single gate on Scan All Jobs covers all current credit use.

Decisions (confirmed with owner 2026-06-01)

  • Build now on the current extension as v6.13 — a small money-safety gate worth having before the v7 extension rework. (Roadmap: data export → v6.14, landing/UX polish → v6.15.)
  • Exact-count dialog. Load the job list first (free — no credits), then confirm: "Scan N unscored jobs? This uses credits — you have X." Buttons: Cancel / Scan N.
  • Always confirm. No "don't ask again" toggle — it's a money action and scanning a page is infrequent enough that a prompt each time is fine.

Flow

  1. Click Scan All Jobs → scanAllJobs() runs as today through fetching the posting list and computing toScore (content.js:301) — all free, no credits spent yet.
  2. If toScore.length === 0: existing "All jobs already scored." path, no dialog.
  3. Else show the confirmation (count = toScore.length, balance from chrome.storage.local.creditBalance, same source as the credits chip).
  4. Cancel (or backdrop click / Esc): reset the buttons (re-enable Scan, disable Stop) and return — nothing scanned.
  5. Scan N: proceed into the existing scan loop unchanged.

The confirmation is inserted right after the toScore empty check (content.js:305), so no /scan call has happened when the user decides. Note the hard-exclusion pre-filter (ADR 0018) may skip some of the N for free, so "Scan N" is an upper bound — fine for a confirmation.

UI

An overlay rendered inside #ww-ext-sidebar (a DOM child) so it inherits the sidebar's --s-* theme variables and the .ww-light override for free. The sidebar slides via transform (sidebar.css:148), which would trap a position: fixed child inside the 340px panel — so the overlay uses position: absolute; inset: 0 within the (positioned) sidebar: a dimmed backdrop over the panel with a centered card. The "Scan N" button mirrors #ww-ext-scan (primary); "Cancel" is neutral/bordered.

Files

  • ext/src/content.js — add confirmScan(count, balance) returning a Promise<boolean> (builds the overlay, wires Cancel/Scan/backdrop/Esc, resolves, removes itself); restructure scanAllJobs() to await it after the toScore check and bail cleanly on cancel.
  • ext/src/sidebar.css — .ww-ext-confirm-* classes (backdrop, card, title, message, actions, buttons) using the existing tokens.
  • ext/manifest.json — version bump.
