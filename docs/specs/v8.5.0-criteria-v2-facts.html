v8.5.0 — Criteria v2: facts + free text

Goal

Implement ADR 0041: match_criteria v2 holds concrete facts only (work auth, locations, work modes, target term, term lengths, languages); all importance/dealbreaker signal moves to the preferences text ("In your own words, what matters most?"), which the scoring prompt reads with importance inferred from phrasing. Weights and tiers disappear from schema, prompt, wizard, and editor. Legacy v1 rows convert at read time server-side.

Files

  • server/app/profile/routes.py — MatchCriteria v2 (replaces WeightedCriterion fields).
  • server/app/profile/db.py — read-time v1→v2 conversion where the row is loaded (preferred values → fact lists), so every consumer (profile API, scorer) sees v2.
  • server/app/scoring/gemini.py — criteria serializer emits fact lines; tier/weight formatting removed.
  • server/app/scoring/prompts.py — weigh notes by phrasing; excluded gate = work-auth conflict or explicit user statement (no tier reference).
  • server/pyproject.toml — minor bump (behavior change).
  • web/src/types.ts — v2 types, setupDone on facts.
  • web/src/pages/PreferencesSetup.tsx — wizard steps lose importance pickers; final step becomes "In your own words".
  • web/src/pages/Preferences.tsx — facts editor + the one text box; fine-tune tiers and importance selects removed.
  • web/src/pages/Account.tsx — snapshot rows read v2 keys.

Slices

  • v8.5.0 — docs: this spec + ADR 0041.
  • v8.5.1 — server: schema v2 + conversion + prompt.
  • v8.5.2 — web: wizard + editor + types on v2.

Verify

  • GET /profile on a row saved under v1 returns v2 facts (preferred values carried over); saving from the new UI round-trips.
  • A scan prompt (log/inspect) shows fact lines + notes, no [must]/tier text anywhere.
  • Wizard and editor render no importance/tier controls; gate and checklist still derive correctly for old, new, and empty profiles.
  • tsc + web build clean; server imports clean.

Notes

  • Conversion is lossy by decision (weights/tiers dropped) — ADR 0041 consequences.
  • The scorer behavior change ships to production only when dev merges to master (ADR 0039); no DB migration involved.
