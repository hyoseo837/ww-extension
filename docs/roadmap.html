Roadmap

Vision across major versions. Living document — updated in place across version bumps, not archived. For active-version phase detail see docs/specs/; shipped majors' specs are archived under docs/archive/vNN/ (ADR 0014); for system architecture see docs/architecture.html.

Direction (decided 2026-06-10)

Per ADR 0042: the project is a portfolio flagship — a complete, shipped, revenue-capable product whose primary payoff is the owner's career. v8 is the final major for now; no v9 is planned. Effort shifts to marketing and user acquisition among UWaterloo co-op students, aimed at the September 2026 recruiting wave. Revisit with real adoption data at the end of Fall term 2026 (December): meaningful organic use reopens feature work around growth; otherwise the project stays a maintained portfolio piece. The subscription / term-pass question is deferred to that review.

Shipped (frozen)

v01 — core scoring loop
Sidebar UI, Gemini scoring, save-to-folder, badge tooltips. Foundation for the entire extension.
v02 — context + cost-efficiency
PDF profile upload, multimodal extraction, soft preferences, context caching, responseSchema, light/dark theming, cumulative token usage.
v03 — UX polish
First-run welcome page, in-extension help, sidebar empty-state guide, options-page help icons, Settings tab About/How-to cards. Extension feels self-contained and Web-Store-ready.

v4 — Monetization (shipped)

Shipped & frozen. Turned the extension into a monetizable service: a FastAPI backend in server/ (monorepo, ADR 0010) holds user accounts, an append-only credit ledger, and the Gemini logic + prompts, with the extension a thin client that authenticates, spends credits per scan, and shows results — moving the proprietary prompts and key management off the client. Stack locked in v4 planning: FastAPI (ADR 0009) on DigitalOcean App Platform (ADR 0007), Supabase auth + Postgres (ADR 0008), Stripe Checkout + webhook credit grants (ADR 0012), with a per-token MARGIN dial in pricing.py. Per-phase detail (v4.0–v4.7): docs/archive/v04/.

v5 — Profile structure + scoring quality (shipped)

Shipped & frozen. The quality pass — made scoring trustworthy where v4 had treated preferences as one prose field and the profile as a raw resume dump. Replaced the textarea with structured match criteria (work authorization, weighted/tiered locations, term + length, work mode, languages; ADR 0013); switched the profile to a structured JSON profile extracted via a Gemini responseSchema, with supplementary experience/projects and a cv_text fallback (ADR 0015); rewrote the scan prompt to a 1–20 scale with a five-band verdict ladder, an Excluded gate, and a per-aspect breakdown (ADR 0016, 0017); and added a credit-free client-side hard-exclusion pre-filter (ADR 0018), with the prompts.py extraction in v5.4–v5.5. Per-phase detail (v5.0–v5.5): docs/archive/v05/.

v6 — UI transition to a web app + admin surface (shipped)

Shipped & frozen (closed 2026-06-01). The UI transition: moved account, profile/CV, match-criteria, and payment management off the cramped options page onto a dedicated web app (Vite + React + TS at ww-extension.hyoseo.dev; ADR 0019, 0020, 0022), leaving the extension a profile reader + in-page scorer with independent sessions joined by a deep link (ADR 0021). Delivered the Warm Editorial design system (Tailwind, ADR 0023; sidebar shell + dashboard home, ADR 0024), the profile/preferences editors, an admin surface (env-allowlisted gift-credit grants on the append-only ledger, with an audit trail), the ext/ restructure (ADR 0026), the legal/trust + support pages (Privacy/Terms, refund policy ADR 0028), data-subject rights — export + hard-delete account (ADR 0027 / 0029) — the credit-use confirmation, and landing/UX polish. Per-phase detail (v6.0–v6.15): docs/archive/v06/.

v7 — Extension fix: website integration + Web Store approval (shipped)

Shipped & frozen. Turned back to the Chrome extension to make it work cleanly against the v6 web app and pass Chrome Web Store review; sequencing held the approval gate ahead of the redesign (compliance → approve → redesign). Delivered: MV3 compliance by self-hosting the last remote resource (Google Fonts) and binding all resources local (ADR 0030) — approved & published as 7.1.1 on 2026-06-04 (live, publisher hyoseo.dev; the rejected 0.1.0 was the old v03 build, not current ext/); the sidebar redesign — light-mode only, Flash-only scoring with the Model tab removed (ADR 0031, 0032), toolbar opens the web app (ADR 0035); billing re-margin to ~1 credit/scan + bonus packs (ADR 0034); and UWaterloo (Microsoft Entra) sign-in replacing Google as anti-abuse (ADR 0036), with extension key-id parity pinned (ADR 0033). Per-phase detail (v7.0–v7.5): docs/archive/v07/. Operational close-out (Stripe live-mode smoke test) carried into v8.

v8 — Maintenance & polish (active)

Opened 2026-06-05 as a rolling maintenance major: cleanup, small fixes, and minor bugs now that the product is in production (per v8.0 open spec). Scope isn't fixed up front — items are collected as they surface and shipped as v8.x. Strand order: cleanup first (low-risk hygiene on what shipped fast — dead code, stale doc links, copy/naming inconsistencies, no behaviour change), then small fixes / minor bugs as the backlog fills in (tracked on the whiteboard's Existing Bugs list). Process is scaled to the change: trivial fixes ship as a v8.x commit without a full spec; non-trivial changes or real decisions still get a spec / ADR.

The v8 slot previously held the extension JS→TS migration, dropped 2026-06-05 (ADR 0037) — the number is reused here; the migration lives in "Further out" below.

Planned queue (added 2026-06-11, ADR 0046) — a full-repo audit (findings) produced a hardening batch, sequenced so tests exist before money code is touched. Organic small fixes still interleave as v8.x commits.

  1. v8.8 — server tests + CI + version hygiene (spec): pytest + ruff + GitHub Actions; pyproject version catch-up.
  2. v8.9 — credit-flow hardening: refund scans stranded pending by a restart; per-user lock on the debit so concurrent scans can't overdraw; server-side input size caps.
  3. v8.10 — server resilience: rate limiting on free endpoints, one retry on transient Gemini failures, DB check in /health, error monitoring (tool choice decided at phase time).
  4. v8.11 — extension polish: split content.js, "retry failed" batch affordance, server-side default model, dead-code removal.

A portfolio strand runs in parallel, owner-gated and not version-bound: GitHub repo description/topics, GitHub Pages for docs/, whiteboard cleanup, and the reaffirm-or-scrub call on ADR 0045's key-in-history (the repo is public). If time runs short before September, v8.8 + v8.9 are the must-ships; v8.10/v8.11 degrade to later.

Further out (uncommitted)

Candidates still on the table, no commitment yet — revisit at phase-planning time: cover-letter generation, re-score on demand, and team / recruiter views. The extension JS→TS migration sits here too, de-committed (ADR 0037) — revisit only if a build step earns its keep some other way. Non-Gemini provider / multi-model support is no longer on the scoring path — scoring standardizes on Gemini Flash (ADR 0031); a future ADR would have to reopen it.
