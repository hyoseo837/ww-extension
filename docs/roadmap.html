Roadmap

Vision across major versions. Living document — updated in place across version bumps, not archived. For shipped phase detail see docs/specs/; for system architecture see docs/architecture.html.

Shipped (frozen)

v01 — core scoring loop
Sidebar UI, Gemini scoring, save-to-folder, badge tooltips. Foundation for the entire extension.
v02 — context + cost-efficiency
PDF profile upload, multimodal extraction, soft preferences, context caching, responseSchema, light/dark theming, cumulative token usage.
v03 — UX polish
First-run welcome page, in-extension help, sidebar empty-state guide, options-page help icons, Settings tab About/How-to cards. Extension feels self-contained and Web-Store-ready.

v4 — Monetization (active)

Goal: turn the extension into a monetizable service. A separate backend repo (WW-extension-backend) holds user accounts, a credit ledger, and the Gemini-calling logic + prompts (moving them off the client so they aren't shipped in the unpacked extension). The extension becomes a thin client: authenticates the user, spends credits per scan, displays results.

Rationale for split:

  • Hide proprietary scoring prompts and tuning logic.
  • Centralize Gemini key management — user no longer needs their own paid API key.
  • Enable per-user billing (credits) without trusting the client.

Stack and platform locked in v4 planning (2026-05-27):

  • Backend: FastAPI on Python 3.12+ (ADR 0009).
  • Deploy: DigitalOcean App Platform (ADR 0007).
  • Auth + DB: Supabase (Google OAuth provider; managed Postgres for the credit ledger) (ADR 0008).
  • Payments: Stripe Checkout (hosted page) + webhook-driven credit grants. ADR to be written at v4.5 planning.

Phase arcs:

  1. v4.0 — Doc restructure + v4 opening (shipped as v4.0.0 and v4.0.1). See docs/specs/v4.0.0-restructure.html.
  2. v4.1 — Backend bootstrap — separate repo created; /health live on DO App Platform; Supabase project configured with Google OAuth; this repo's api.html + architecture.html updated. No extension code changes. See docs/specs/v4.1.0-backend-bootstrap.html.
  3. v4.2 — Auth in the extension — sign-in via chrome.identity.launchWebAuthFlow, Supabase session JWT stored, sign-out. Extension can authenticate against the backend.
  4. v4.3 — Credit ledger — server-side balance, debit on scan, refund on failure. Extension shows balance. Scoring still uses the extension's own Gemini key in this phase.
  5. v4.4 — Server-side scoring — Gemini calls move to the backend. Extension sends posting payload, backend returns score. Removes API-key requirement from the extension.
  6. v4.5 — Stripe credit purchase — Stripe Checkout integration, webhook-driven credit grants, purchase UI in options page.
  7. v4.6 — Free tier + paid tier UX — onboarding tweaks, welcome page updates, pricing display.

Phase numbering above is the plan of record; sub-commits within a phase use the Z digit per ADR 0002. Slicing may still shift if a phase grows too large — promote to a new Y bump rather than overloading one phase.

Out of scope for v4 (deferred): auto-apply, cover-letter generation, non-Gemini providers, native mobile.

Beyond v4

No v5 commitments yet. Candidates to consider once v4 stabilizes: non-Gemini provider support, cover-letter generation, team / recruiter views. Update this section when a v5 direction is set.
