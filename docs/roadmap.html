Roadmap

Vision across major versions. Living document — updated in place across version bumps, not archived. For shipped phase detail see docs/specs/; for system architecture see docs/architecture.html.

Shipped (frozen)

v01 — core scoring loop
Sidebar UI, Gemini scoring, save-to-folder, badge tooltips. Foundation for the entire extension.
v02 — context + cost-efficiency
PDF profile upload, multimodal extraction, soft preferences, context caching, responseSchema, light/dark theming, cumulative token usage.
v03 — UX polish
First-run welcome page, in-extension help, sidebar empty-state guide, options-page help icons, Settings tab About/How-to cards. Extension feels self-contained and Web-Store-ready.

v4 — Monetization (active)

Goal: turn the extension into a monetizable service. A separate backend repo (TBD name) holds user accounts, a credit ledger, and the Gemini-calling logic + prompts (moving them off the client so they aren't shipped in the unpacked extension). The extension becomes a thin client: authenticates the user, spends credits per scan, displays results.

Rationale for split:

  • Hide proprietary scoring prompts and tuning logic.
  • Centralize Gemini key management — user no longer needs their own paid API key.
  • Enable per-user billing (credits) without trusting the client.

Sketched phase arcs (subject to v4 planning):

  1. v04.000 — Doc restructure + v4 opening (this commit). See docs/specs/v04.000-restructure.html.
  2. Backend bootstrap — separate repo created; minimal auth + health endpoints; docs/reference/api.html populated.
  3. Auth in the extension — sign-in flow, token storage, sign-out. Extension can authenticate against the backend.
  4. Credit ledger — server-side balance, debit on scan, refund on failure. Extension shows balance.
  5. Server-side scoring — Gemini calls move to the backend. Extension sends posting payload, backend returns score. Removes API key requirement from the extension.
  6. Payment processor integration — credit purchase flow (Stripe / Ko-fi / LemonSqueezy — TBD).
  7. Free tier + paid tier UX — onboarding tweaks, welcome page updates, pricing display.

Phase numbering and exact slicing will be set during v4 planning (the next session after this restructure). Treat the list above as a rough sequence, not a commitment.

Out of scope for v4 (deferred): auto-apply, cover-letter generation, non-Gemini providers, native mobile.

Beyond v4

No v5 commitments yet. Candidates to consider once v4 stabilizes: non-Gemini provider support, cover-letter generation, team / recruiter views. Update this section when a v5 direction is set.
