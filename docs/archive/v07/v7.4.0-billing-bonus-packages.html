v7.4.0 — Bonus packages + re-margin

Tier amounts below were revised in v7.4.2 (dropped $1, retuned bonuses); the bonus model + re-margin decision here still stand.

Goal

Reprice per ADR 0034: a scan costs ~1 credit (raise MARGIN), the entry pack is $1 / 100 credits, and bigger packs include bonus credits ($5 → 550, $10 → 1200). Token-based pricing and the extract flow are unchanged; only the dial, the package tables, and the web copy move.

Files (one commit — server + web package tables must stay in sync)

  • server/app/billing/pricing.py — MARGIN 5.0 → 10.0; update the calibration docstring (now ~1 credit/scan, ~100 scans per bonus).
  • server/app/billing/payments.py — replace CREDIT_PACKAGES with credits_100 / credits_550 / credits_1200 ($1/100, $5/550, $10/1200); update the "cad_cents == credits" comment to note the bonus.
  • web/src/packages.ts — mirror the new tiers + bonus notes; update the "no bulk discount" comment.
  • web/src/pages/Buy.tsx, web/src/pages/Landing.tsx, web/src/pages/Account.tsx — copy: "~1 credit per scan, bigger packs include bonus credits" (drop the bare "1 credit = $0.01").
  • server/pyproject.toml — version bump (ADR 0010, server touched).
  • ext/manifest.json — repo version bump (ADR 0002).

Verify

  1. A live Flash scan debits ≈ 1 credit (token-based, so ~0.8–1.2).
  2. POST /credits/checkout for credits_550 creates a Stripe session charging $5 with line item "550 credits"; on checkout.session.completed the ledger is granted 550 (bonus included), idempotent on the event id (ADR 0012).
  3. Web Buy + Landing show 100 / 550 / 1200 at $1 / $5 / $10 with the bonus called out; tsc clean.
  4. Server and web package ids/amounts match exactly.
