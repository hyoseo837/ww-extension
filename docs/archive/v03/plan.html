ww-extension — v03 Project Plan

Where v02 ended

v02 (commits v02.001 through v02.022) added high-quality candidate context (PDF profile upload + Gemini multimodal extraction, soft preferences field), cost-efficient Gemini usage (context caching, responseSchema), light/dark theming, and a cumulative token-usage counter. The extension is feature-complete and functionally solid, but it assumes the user has read the README: there is no in-extension guidance, no privacy/about info, and the sidebar mixes the primary "Scan" action with the secondary "Save to Folder" feature in one undifferentiated block.

v02 documents are archived at docs/v02-archive/. All new work is documented in this file and its siblings docs/impl.html / docs/history.html.

Scratchpad plan used during v03 design session: ~/.claude/plans/let-s-do-some-planning-declarative-lemur.md.

v03 Vision

v03 makes the extension feel self-contained and finished. A new user should be able to install it, understand what it does, complete setup, and trust it — entirely without leaving the extension or reading the README. Day-to-day users get a cleaner sidebar where the main action (Scan) is visually dominant and the folder workflow is its own clearly labelled section.

Confirmed v03 features (in implementation order)

v03.002 — Archive v02 docs + open v03 docs (this phase)

Moves the current v02 docs into docs/v02-archive/ and writes fresh docs/plan.html, docs/impl.html, and docs/history.html for v03. No code changes.

v03.003 — First-run welcome page

A new welcome.html extension page with three numbered steps: (1) Get a Gemini API key, (2) Paste key + upload CV, (3) Open WaterlooWorks and scan. Two CTAs: "Open Settings" and "Skip for now". The page matches the extension's dark/light design and reads theme from storage to apply the correct palette.

src/background.js gains a chrome.runtime.onInstalled listener that opens welcome.html in a new tab on first install. A welcomeShown storage flag prevents re-opening on dev reloads. A new openWelcome message type in the background lets any context open the welcome page later.

Re-entry points: a ? header button in the WW sidebar (between the settings gear and close buttons), and a "Show welcome page again" button added to the Settings tab in v03.005.

v03.004 — Sidebar controls restructure

Restructures #ww-ext-controls from a flat flex-wrap block into two named sections: Scan (Scan All Jobs + Stop) and Save to Folder (Score ≥ filter + verdict pills + Save to Folder + Clear). A section label and a border-top divider separate the two.

Scan All Jobs gets taller (44 px) and larger font (15 px) to visually dominate the panel. Save to Folder and its filter controls are visually subordinate — smaller section label, secondary styling. The per-card folder icon (previously opacity: 0.3) bumps to 0.55 for discoverability.

A ? button on the "Save to Folder" section label opens an inline tooltip explaining score threshold + verdict meanings. Uses a new #ww-ext-help-tooltip element (separate from the badge tooltip).

v03.005 — Sidebar empty-state guide

Replaces the plain "No jobs scored yet" text with a three-step get-started card. Steps 1 and 2 show live status — a checkmark circle if the API key is set / CV text is present, an unlit number otherwise. Step 3 lights up after the first scan completes. An inline "Settings" link opens the options page.

The guide updates in real-time via chrome.storage.onChanged so the checkmarks appear immediately when the user fills in the options page in another tab.

v03.006 — Options page: (?) help icons

Small ? buttons added next to three confusing elements in the options page. Each toggles a caret-popover on click; clicking outside dismisses it. No external library — pure CSS + a few lines of JS.

  • Model dropdown — "Flash is cheaper and fast. Pro is more accurate but roughly 10× the cost per token."
  • Token Usage card — explains Input / Output / Cached columns and links to Gemini pricing.
  • Custom Match Criteria — example: "Only remote roles in Canada; no Web3 companies."

v03.007 — Options page: Clear CV text button

A "Clear CV text" secondary button on the Profile & Context tab, next to the "Extracted Profile" card heading. On click: confirm() prompt, then clears cvText from storage and empties the textarea. Scoped to CV text only — does not touch the API key, preferences, token counter, or scores.

v03.008 — Options page: Settings tab expansion

The Settings tab currently has only the theme toggle. Two new cards are added:

  • How to use (top) — four-step recap of the setup and scan flow, plus a "Show welcome page again" button that opens welcome.html in a new tab.
  • About (bottom) — version number (read live from chrome.runtime.getManifest().version), creator link (hyoseo.dev), GitHub link (hyoseo837/ww-extension), privacy policy link (hyoseo.dev/privacy-policy/ww-extension/), Ko-fi link (ko-fi.com/hyoseo), and a one-paragraph plain-English data handling summary.

Out of scope

Continued from v01/v02: auto-apply, cover-letter generation, non-Gemini providers, backend server.

v03-specific exclusions (deliberately deferred):

  • Auto-open sidebar on WW jobs page load.
  • Toolbar-icon shortcut to trigger a scan (icon still opens Options).
  • Collapsible "Save to Folder" panel in sidebar (visual grouping only).
  • Full "reset all extension data" destructive button (targeted Clear CV is enough).
  • Fix for the scrollToRow "not in current view" papercut from v01 — remains a known limitation.
