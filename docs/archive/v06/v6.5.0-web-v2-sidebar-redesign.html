v6.5.0 — Web v2 design: sidebar shell + dashboard home + landing

Goal

Adopt the second Stitch design iteration (the *_sidebar exports in web/design/) as the live web app. It keeps the same Warm Editorial design tokens (ADR 0023) but changes the app's layout and information architecture: a persistent left sidebar shell replaces the v6.3 top nav, the /account page becomes a dashboard home (welcome + balance + profile snapshot + recent activity) rather than a raw balance/history list, and the logged-out / route gets the full landing page promised in the v6.3.0 spec (hero + feature cards + footer). The shell/IA shift is recorded in ADR 0024. This phase is web-only — no server, manifest behavior, or API changes.

Files

Changed — web/

  • src/Layout.tsx — top nav replaced by a fixed 256px (w-64) desktop sidebar (wordmark + avatar, nav links with the active secondary-container pill, Buy Credits CTA, sign out) and a sticky mobile top bar; main content offsets md:ml-64.
  • src/pages/Account.tsx — reworked into the dashboard home (account_dashboard screen): "Welcome back" header, balance card, profile snapshot (CV status / top location / target term, with Edit profile + Edit preferences links), recent-activity card.
  • src/pages/Profile.tsx, src/pages/Preferences.tsx — sticky save bar offset md:left-64 so it clears the sidebar (the only change; both pages already used the design tokens).
  • src/pages/Landing.tsx — rebuilt to the landing_page_logged_out screen: minimal header wordmark, hero (AI-Powered Matching pill, serif headline, subcopy, Google sign-in), 3 feature cards, footer.
  • tailwind.config.js — add the display-lg-mobile token (Source Serif 4, 32px/40px/600). It is listed in the design system (web/design/.../DESIGN.md) and used by the dashboard/landing headings, but was omitted from the v6.3 config port, so text-display-lg-mobile silently produced nothing.

Moved / reorganized — web/design/ (reference only, outside the build)

  • Replaced the first-iteration screens with the second-iteration *_sidebar exports (account_dashboard, buy_credits_sidebar, billing_history_sidebar, candidate_profile_sidebar, match_preferences_sidebar, admin_dashboard_sidebar, landing_page_logged_out, extension_sidebar_job_scan); refreshed design.md and warm_editorial/DESIGN.md.

Verify

  1. cd web && npm run build is clean (tsc + Vite, no errors).
  2. Logged in: a persistent left sidebar shows on desktop with the active link highlighted; main content clears it (no overlap); the mobile top bar appears below md. The dashboard home matches account_dashboard; Profile/Preferences sticky save bars sit flush to the right of the sidebar, not under it.
  3. The dashboard "Welcome back" heading renders in Source Serif 4 at 32px on mobile (not body text) and 48px at md+.
  4. Logged out: / renders the full landing (pill, hero, 3 feature cards, footer) and Sign in with Google still works.
  5. Functionality unchanged: balance, credit history, profile/preferences save, and the Stripe buy round-trip all still work.

Notes

Buy / Billing carry over unchanged. Both were built to the design tokens in v6.3 and read correctly inside the sidebar shell, so they are not edited here. Buy keeps the real packages (500/$5, 1000/$10, 2000/$20) mirroring payments.py; the Stitch "Save %" / 1,500 / 5,000 tiers remain illustrative only.

Preferences has no sidebar nav entry by design — it is reached from the dashboard profile snapshot ("Edit preferences") and from Profile. The four nav items stay Dashboard / Credits / History / Profile.

Admin (admin_dashboard_sidebar) is v6.6 — it needs backend work (admin authZ + gift-credit grants) and is specced separately.
