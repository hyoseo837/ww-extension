v6.0.0 — Open v6: archive v5, web-app direction locked

Goal

Open major version 6. v5 shipped the scoring-quality pass and is now frozen; v6's theme is the UI transition — moving account, profile/CV, match-criteria, and payment management off the extension's cramped options page and onto a dedicated web app, plus an operator-only admin surface. This phase is pure docs: archive v5, flip the roadmap, and record the four decisions that lock v6's shape before any code is written. No client, server, or web code changes here.

The web app is a new client of the existing FastAPI API, not a re-architecture: profile and credit state already live server-side behind authenticated endpoints, and POST /scan reads the stored profile (no client-sent profile since v4.4.2), so the editing UI can move with zero impact on scanning.

Notes

Phase sequence locked for v6 (detail lives in each phase's own spec when written):

v6.1 — web app bootstrap
Scaffold web/ (Vite + React + TS), Supabase Google sign-in, signed-in shell, deploy to the subdomain, backend CORS + Supabase redirect config. Architecture doc updated here.
v6.2 — account + credits on web
Balance, credit history (adds GET /credits/history), Buy credits via Stripe with a real success_url.
v6.3 — profile editor on web
Structured profile, CV upload + extract, supplementary entries, match criteria, notes — the core "bad UI" fix.
v6.4 — extension slim-down
Options page → thin (signed-in state, balance, Manage account →, local toggles only); extension becomes a profile reader (fetches match_criteria via GET /profile for the ADR 0018 pre-filter); out-of-credits nudge + Buy button deep-link to web; profile_not_set routes new users to the web app; welcome page repointed.
v6.5 — landing / introduction page
The logged-out marketing/intro view of the web app.
v6.6 — admin surface
Operator-only user list/inspect (balance, ledger, scan activity) and gift-credit grants (new ledger kind); admin authZ via an env allowlist enforced in a FastAPI dependency + audit trail — its own ADR at that phase.

Out of scope for v6 (stay on the whiteboard): re-score feature, scan/extraction prompt upgrades, multi-model support, and the extension JS→TS migration.
