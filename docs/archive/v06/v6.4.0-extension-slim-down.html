v6.4.0 — Extension slim-down

Goal

Now that account, profile, and payment management live on the web app (v6.2–v6.3), strip those surfaces out of the extension and point users to the web app instead. The options page keeps only what's genuinely extension-local — model choice, sign-in/balance, theme, the hard-filter toggle — plus deep links to the web app. The scan flow is unchanged; the extension keeps its own session (independent, ADR 0021) and still reads match_criteria from GET /profile at scan time for the ADR 0018 pre-filter (already the case — no profile-editing UI needed for that).

Files

Changed — options.html + src/options.js

  • Remove the Profile & Context tab entirely (CV upload + extract, structured profile view, supplementary entries, work-authorization, match criteria, additional notes) — all now on the web app's /profile + /preferences.
  • Remove the in-extension Buy credits Stripe buttons; replace with a Manage account & credits → link to the web app (/account) and an Edit profile & preferences → link (/profile).
  • Keep: Model tab; Account (Google sign-in / email / live balance / sign-out); Settings (theme, hard-filter toggle, About). Update the How-to copy and About text to reflect web-app management.
  • options.js drops the profile/extract/supplement/criteria /buy code (and their helpers) and the on-sign-in loadProfileFromServer; adds the web deep-link handlers.

Changed — src/content.js + src/background.js

  • Out-of-credits nudge (content.js): the "Buy credits" button opens the web app's /buy instead of the options Account section.
  • PROFILE_NOT_SET (background.js): message points users to set up their profile on the web app; the sidebar surfaces a link to /profile.
  • New background.js message openWebApp { path } → chrome.tabs.create({ url: WEB_APP_URL + path }) (WEB_APP_URL = https://ww-extension.hyoseo.dev). Content scripts can't open tabs directly, so they route through it.

Changed — welcome.html

  • Step 2 ("Upload your application package") repointed: set up profile on the web app rather than the options Profile & Context tab.

Changed — docs

  • docs/architecture.html — options page is now thin; profile editing is web-only; the extension reads match_criteria at scan time. manifest.json version bumps per slice.

Verify

  1. Options page shows only Model + Settings (with Account); no Profile & Context tab, no in-extension Buy buttons. "Manage account →" / "Edit profile →" open the web app.
  2. Sign-in still works and the balance renders; sign-out clears it.
  3. Theme toggle and the hard-filter toggle still work and persist.
  4. A scan with no profile set returns the PROFILE_NOT_SET path and the sidebar links to the web app's /profile.
  5. An out-of-credits scan halt shows the nudge; its button opens the web app's /buy.
  6. A normal scan (signed in, profile + credits present) still scores, including the hard-filter pre-filter (reads match_criteria from GET /profile).
  7. node --check passes on the changed JS; the unpacked extension loads.

Notes

Extension styling is untouched here — the options page keeps its existing dark/light theme. The sidebar/options restyle to the web app's warm tokens is a separate, later pass (deferred until this surface settles).

Stripe shim retires for the extension. With the extension no longer initiating checkout (Buy moves to web), the chrome-extension /credits/checkout/result shim is now only theoretical for the extension path; the backend endpoint stays (harmless) but the extension no longer calls createCheckout.
