Inherited State (from v02.022)

Files (working tree)

  • manifest.json — MV3, version 3.0.0, options_ui.open_in_tab: true, action: {} (no popup)
  • options.html + src/options.js — three-tab settings UI (API Configuration, Profile & Context, Settings)
  • src/content.js — content script: bridge, sidebar, scan flow, scrollToRow, theme listener
  • src/background.js — Gemini client, token counter, message router
  • src/page-bridge.js — page-context bridge for WW DOM operations
  • src/sidebar.css — all extension CSS (sidebar vars, badge styles, controls)
  • docs/examples/ — WW DOM reference (don't read the 553 KB file; use the 15 KB compact version)

chrome.storage.local keys

  • apiKey, model, cvText, preferences — settings
  • theme — 'dark' (default) or 'light'
  • tokenUsage — { input, cached, output } cumulative counters
  • ww_scores — Map of postingId → {score, verdict, reason, title, org}
  • ww_posting_ids — ordered array from selectAll, used for cross-page navigation

Key architectural decisions to preserve

  • page-bridge.js runs in page context to access dataViewerApp, action tokens. Content script ↔ page via postMessage with reqId namespacing.
  • Fetch goes directly to /myAccount/co-op/full/jobs.htm with cached tokens — bypasses getPostingOverview() to kill overlay flicker. Do not revert.
  • MutationObserver on <table> with rAF-debounced badge reinject — DataViewer reuses <tr> elements on page change.
  • API key sent as X-Goog-Api-Key header (not query string) — keeps key out of browser history.
  • Token accumulation serialized through a per-context tokenWriteChain promise — prevents lost-update races.
  • chrome.storage.onChanged in content script drives live theme + (new in v03) guide-step updates.
