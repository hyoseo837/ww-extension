A. Factual basis (what the app actually does)

Both documents draw on these facts — keep this list current.

Data collected / processed

Account identity
Email address and Google account, via Google OAuth through Supabase Auth; a Supabase user_id. No password is stored (OAuth only).
Candidate profile
CV text and the structured profile extracted from the uploaded application package (education, experience, skills, projects, languages, grade-report / co-op-history / cover-letter raw text), match criteria / preferences, and free-form notes. User-provided.
Usage records
Scan records (job postings scored: org, title, posting id, model used, cost, timestamps, and the AI result) and the credit ledger (purchases, scan debits/refunds, admin grants).
Payment
Handled by Stripe. The app stores ledger entries and a Stripe customer/session reference — not card numbers (Stripe holds those).
Job-posting content
WaterlooWorks posting text the user scans is sent (with their profile) to Google Gemini for scoring.
Local-only (extension)
Settings, theme, score map, token usage live in chrome.storage.local on the user's machine.

Sub-processors / third parties (who receives what)

  • Supabase — auth + Postgres database (account, profile, ledger, scans). Region ca-central-1 (Canada).
  • Google — OAuth (sign-in) and the Gemini API (receives CV/profile + job description for scoring). Backend-owned key.
  • Stripe — payment processing.
  • DigitalOcean — backend hosting (tor1, Canada).
  • Vercel — web app hosting.
  • Cloudflare — DNS + email routing for support@hyoseo.dev.

Other facts

  • No tracking cookies / analytics. Auth uses localStorage; no third-party analytics or ad tech.
  • Contact: support@hyoseo.dev.
  • Not affiliated with the University of Waterloo or WaterlooWorks.
  • Data-subject controls already planned: account deletion (v6.9, hard delete via cascade) and data export (v6.12).
