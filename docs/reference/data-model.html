Data Model

All persistent state. Updated whenever a storage key is added, removed, or its schema changes.

Client — chrome.storage.local

apiKey
Type: string. Gemini API key. Read only by the background service worker; never enters the content-script context. In v4 this becomes optional / removed once server-side scoring lands.
model
Type: string ('gemini-2.5-flash' | 'gemini-2.5-pro' — verify against current options page).
cvText
Type: string. Extracted profile text from the user's uploaded PDF. Used as scoring context. User-facing name: "application package."
preferences
Type: string. Soft preferences / custom match criteria (free-form prose).
theme
Type: 'dark' | 'light'. Default 'dark'. Live-synced via chrome.storage.onChanged across all extension contexts.
tokenUsage
Type: { input: number, cached: number, output: number }. Cumulative token counters across all scans. Writes are serialized through tokenWriteChain in the background service worker to prevent lost-update races.
ww_scores
Type: Record<postingId, { score: number, verdict: string, reason: string, title: string, org: string }>. Score map keyed by WW posting ID. Drives badge rendering and sidebar list.
ww_posting_ids
Type: string[]. Ordered array from the last selectAll. Used for cross-page row navigation when the user clicks a sidebar entry on a different results page than where it was scored.
welcomeShown
Type: boolean. Set after the first-install welcome tab opens. Prevents re-opening on dev reloads (which fire onInstalled with reason 'update').
droppedFile
Type: options-page transient state for the last-dropped PDF (filename + base64). Cleared by the "Clear application package" button.

Server — backend repo (not yet built)

Backend schemas (users, credit ledger, scan history, payment records) will be documented here once the backend bootstrap phase lands. Until then, see docs/roadmap.html#active for the planned v4 arc and docs/decisions/0004-backend-separate-repo.html for the repo-split rationale.

Anticipated entities (subject to v4 design):

  • user — identity + auth credentials
  • credit_balance — per-user credit count
  • credit_ledger_entry — append-only debit/credit log (scan debits, purchase credits, refunds)
  • scan — request/response record for audit and refund-on-failure
