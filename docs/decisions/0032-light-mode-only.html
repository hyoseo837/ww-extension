ADR 0032 — Light-mode only, no theme toggle

Context

The extension ships two themes, dark (default) and light. Each shipped page carries both token sets and a switch:

  • options.html — a dark :root plus a body.light override, and a Theme card in Settings (the #themeToggle pill).
  • options.js — applyTheme() + the toggle handler persist the choice to chrome.storage.local under a theme key and read it back on load.
  • content.js / sidebar.css — the in-page sidebar mirrors the same dark/light tokens via applyThemeToContent() and a storage.onChanged listener on theme.

The v7.3 sidebar design sheet (ext/design/extension_sidebar_job_scan/) is a single warm editorial light look. Carrying a dark token set and a runtime toggle through that redesign doubles the styling surface, adds a stored key and its change-listener to maintain, and keeps a settings control the minimal-options direction (ADR 0031) wants gone.

Decision

The extension standardizes on a single light theme. There is no theme toggle and no dark mode. Concretely:

  • The options-page Theme card and the #themeToggle control are removed; applyTheme() and the toggle handler go with them.
  • The theme storage key is no longer read or written by the client. Any residual stored value is ignored (no migration needed — it is display-only state).
  • Each shipped page keeps one set of tokens — the former body.light values promoted onto :root; the dark :root and the body.light override are deleted.

This ADR governs the whole client, but lands in slices: the options page goes light-only with the Model-tab removal (first v7.3 slice); the sidebar (content.js + sidebar.css: the theme listener, applyThemeToContent, and the dark tokens) is converted in the sidebar-restyle slice that adopts the design sheet.

Consequences

  • Easier: one token set per page; no theme key, handler, or change-listener to carry through the redesign; one fewer settings control (closer to the ADR 0031 "auto-skip + sign-in only" target).
  • Harder / lost: users who preferred dark mode lose it. Accepted — the redesign is a single deliberate light look, and a personal-scale tool does not need a theme system.
  • Constrains: v7.3 (and the v8 TS migration after it) must not re-introduce dark tokens or a toggle. Pairs with ADR 0030 (self-host all shipped resources) as a styling constraint on the redesign.
  • Until the sidebar slice lands, the in-page sidebar still honors a stored theme; once that slice ships, the key is fully dead.
