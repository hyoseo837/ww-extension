ADR 0008 — Auth and database via Supabase

Context

v4 needs user authentication and a Postgres database for the credit ledger. Auth is constrained by the Chrome-extension client: a thin UI inside the options page, no good place to host a password-reset email flow, no incentive to roll bot defense by hand.

Three viable auth shapes were considered:

  1. Own it. Google OAuth via chrome.identity.launchWebAuthFlow, FastAPI verifies the Google ID token and issues its own session JWT + refresh token. Zero vendor cost, ~150 lines of FastAPI plus token-refresh logic in the extension.
  2. Clerk. Managed auth with documented Chrome-extension flows. Auth only — Postgres still has to be hosted somewhere else.
  3. Supabase. Managed auth (Google OAuth provider, refresh tokens, session storage) and managed Postgres in one product. Documented Chrome-extension flow.

Email/password was rejected outright: friction on the extension UI, hand-rolled password reset, and no upside over Google OAuth for a Waterloo-student user base.

Decision

Use Supabase for both authentication and the credit ledger Postgres database. The extension authenticates via chrome.identity.launchWebAuthFlow against Supabase Auth (Google OAuth provider), receives a Supabase session JWT, and forwards that JWT to the FastAPI backend on every request. FastAPI verifies the JWT against Supabase's JWKS and connects to the same Supabase project's Postgres for credit-ledger reads and writes.

Consequences

  • + Skip rolling password reset, refresh token rotation, JWKS handling, and OAuth provider integration.
  • + One vendor for auth + DB — single bill, single outage surface to monitor.
  • + Free tier covers v4 launch; paid tier starts at $25/mo if/when needed.
  • + Supabase JWTs are stateless on the FastAPI side — no session table in the backend.
  • − Vendor lock. Migrating off Supabase means re-doing both auth and DB.
  • − Backend depends on Supabase availability for both login and ledger reads.
  • − Two regions to coordinate (Supabase + DO App Platform). Match regions to keep cross-vendor latency low.
  • − Supabase Row-Level Security is tempting but bypassed when FastAPI uses the service-role key — keep ledger writes strictly server-side and document why RLS is not the security boundary here.
