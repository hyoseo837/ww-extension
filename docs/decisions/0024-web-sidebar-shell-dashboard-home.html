ADR 0024 — Web app: persistent sidebar shell + dashboard home

Context

v6.3 applied the first Stitch "Warm Editorial" iteration to the web app: a top navigation shell, with /account as a balance + credit-history page. The user then produced a second Stitch iteration (the *_sidebar exports in web/design/) and chose it as the live design. The visual language and tokens are unchanged (ADR 0023 still governs the palette/type/spacing); what changed is the layout and information architecture:

  • A fixed left sidebar (256px / w-64) replaces the top nav as the primary navigation on desktop.
  • /account becomes a dashboard home (welcome, balance card, profile snapshot, recent activity) rather than the raw balance/history view. Full history moves to its own card / the /billing route.

This is a cross-cutting shell decision: every authenticated page now renders inside the sidebar shell, and a future agent adding a page will re-derive the same offsets unless they are written down.

Decision

  • Adopt the second-iteration sidebar shell as the web app layout. Layout.tsx renders a fixed w-64 desktop sidebar (md:flex) and a sticky mobile top bar (md:hidden); authenticated page content lives in <main class="md:ml-64">.
  • Any element fixed to the viewport that must clear the sidebar (e.g. the Profile/Preferences sticky save bar) offsets md:left-64. This is the shell's one layout contract for new pages.
  • Nav items are Dashboard / Credits / History / Profile. Preferences is intentionally not a top-level nav item — it is reached from the dashboard snapshot and from Profile.
  • /account is the dashboard home (summary surface, read-mostly), distinct from /billing (full credit history) and /buy (purchase).
  • This supersedes the v6.3 top-nav shell. ADR 0023 (tokens) and the v6.3 page-level styling remain in force; only the shell/IA change.

Consequences

  • + A single, persistent navigation surface; the dashboard gives a logged-in user an at-a-glance overview instead of a bare ledger.
  • + One documented layout contract (md:ml-64 for content, md:left-64 for fixed bars) — new pages drop into the shell without re-deriving offsets.
  • − A hardcoded sidebar width (w-64) couples three call sites (sidebar width, main margin, fixed-bar offset). Accepted as minimal-code over a CSS variable / layout-grid abstraction for a four-route app.
  • The dashboard duplicates some data already on /billing (recent activity vs. full history) and /profile (snapshot vs. editor) — intended redundancy for an overview surface, not a new data source.
