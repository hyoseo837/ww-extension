ADR 0005 — Doc architecture: per-phase specs + subject-indexed ADRs

Context

v01–v03 used a three-doc shape: plan.html (vision), impl.html (build steps + inherited state), history.html (chronological decisions log). Three issues surfaced:

  1. Duplication. Plan and impl both enumerate every phase. Phase-level changes had to be reflected in two places.
  2. Mixed time horizons in impl.html. Per-phase build steps (relevant during that phase) were interleaved with the "Inherited State" snapshot (relevant always).
  3. Chronological-only decision log. history.html grouped decisions by phase number. Finding "the auth decision" months later required remembering which phase it landed in.

Research into 2026 patterns (Diátaxis, ADRs, Spec-Driven Development, CLAUDE.md navigation-hub guidance) suggested a cleaner split: specs per phase, ADRs per decision, separate living docs for vision and architecture.

Decision

The v4-onward doc structure is:

  • CLAUDE.md — agent navigation hub at project root.
  • docs/README.html — doc map.
  • docs/roadmap.html — living vision across major versions.
  • docs/architecture.html — living system architecture.
  • docs/specs/vX.Y.Z-slug.html — one spec per phase.
  • docs/decisions/NNNN-slug.html — ADRs, immutable, subject-indexed.
  • docs/reference/ — stable lookup material.
  • docs/archive/v01..v03/ — frozen prior major versions.

Specs are self-contained (goal + files + verify + notes). ADRs follow the Michael Nygard template (Context / Decision / Consequences) with status tracking and supersession links.

Consequences

  • + Agent working on a phase reads a single small file (the relevant spec) instead of cross-referencing plan and impl.
  • + Decisions are findable by topic (ls decisions/*auth*) regardless of when they were made.
  • + Living docs (roadmap, architecture) survive major-version bumps without being rewritten.
  • + Smaller per-task context window — agent loads only what's relevant.
  • − More files. A major version with 16 phases produces 16 spec files instead of one combined impl.html.
  • − Two indirection points to learn: the spec-naming convention and the ADR-numbering convention. docs/README.html documents both.
  • − v01–v03 archived docs use the old shape; agents reading those must understand the prior convention. Mitigated by the archive being read-only and clearly labelled.
