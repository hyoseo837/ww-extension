ADR 0030 — Self-host all extension page resources

Context

The last Chrome Web Store submission was rejected under Content Policies for "Including remotely hosted code in a Manifest V3 item." That rejected artifact was an early build (labelled 0.1.0 because the manifest predates strict versioning) — effectively the old v03 public extension, not the current ext/.

An audit of the current ext/ (v7.0.0) found no remote JavaScript or Wasm: no remote <script src>, no eval / new Function / importScripts / dynamic import(). The one script injection in content.js uses chrome.runtime.getURL('src/page-bridge.js') — a locally packaged web-accessible resource, the correct MV3 pattern.

The only remaining remote resource in a shipped page is Google Fonts, loaded via <link> in options.html (Hanken Grotesk, Inter, JetBrains Mono) and welcome.html (Hanken Grotesk, Inter). Remote fonts/CSS are arguably not "code" under the policy (which targets JS/Wasm), but the ambiguity is not worth carrying into a review we need to pass — and a remote font <link> also leaks the user's IP to a third party on every page open and adds a runtime network dependency.

Looking ahead: the redesign phase intends to adopt the Stitch sidebar design (ext/design/extension_sidebar_job_scan/), whose export pulls Tailwind via CDN, Google Fonts, and Material Symbols remotely. Adopting that verbatim would re-introduce exactly the violation class we are fixing. A standing rule is needed so the redesign cannot regress it.

Decision

Every resource referenced by a shipped extension page must be packaged locally. Specifically, in any page that ships to the Web Store (allowlisted in package.sh):

  • No remote <link> to fonts or stylesheets. Fonts are vendored as local woff2 files with local @font-face declarations.
  • No CDN <script> (e.g. cdn.tailwindcss.com). Any utility CSS must be a locally built/checked-in stylesheet, not a runtime CDN.
  • No remote icon fonts (e.g. Material Symbols) — vendor the glyphs/font locally or use packaged SVGs.
  • No remote JS/Wasm of any kind (already true; restated to keep it true).

Consequences

  • Easier: unambiguous MV3 / Web Store compliance; no third-party requests at runtime (privacy); extension pages work offline.
  • Harder: fonts and icon glyphs must be vendored into the repo and updated by hand; the redesign phase cannot drop in the Tailwind CDN — it must check in a locally produced CSS file instead.
  • Constrains: all future extension pages, and explicitly the redesign phase's adoption of the Stitch design (Tailwind output, fonts, and Material Symbols all self-hosted).
  • The design/ export keeps its CDN links — it is a reference artifact, never in the package.sh allowlist, so it does not ship. This ADR governs shipped pages only.
