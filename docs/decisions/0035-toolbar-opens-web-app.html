ADR 0035 — Toolbar icon opens the web app

Context

The browser-action (toolbar) icon's click handler (background.js, chrome.action.onClicked) opened the extension's options page. Since v6, the account, profile, preferences, and billing surfaces all live in the web app (ww-extension.hyoseo.dev); the options page was reduced (v7.3) to a thin local settings panel (sign-in + auto-skip + How-to + links). So the most useful destination for the toolbar icon is the web app, not the options page — this is v7.3 redesign strand 4.

Decision

  • The toolbar icon's onClicked opens the web app dashboard via chrome.tabs.create({ url: WEB_APP_URL + "/account" }). /account resolves to the dashboard when signed in and to the landing page when signed out (the web app's catch-all route), so it works in both states without the extension knowing the auth state.
  • Direct action, no popup. Keep action with just a default_title (hover label) — no default_popup. A popup would be extra UI for a single redirect; the design calls for the icon to take you to the web app.
  • Options stays reachable — it is not the toolbar destination anymore, but remains available via right-click the icon → Options (options_ui is kept), the in-page sidebar gear, and the welcome page's "Open Settings". No openOptionsPage entry point is lost.

Consequences

  • One-click access to the account/billing surface that actually matters for a paid product; the icon's behavior matches the v6+ "web app is the account home" model.
  • Users who clicked the icon expecting options now land on the web app; acceptable — options is a thin settings panel and still one right-click away.
  • No new permissions (tabs.create needs none for a normal URL). options_ui and action both remain in the manifest.
