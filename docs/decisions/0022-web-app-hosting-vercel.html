ADR 0022 — Web app hosting on Vercel at ww-extension.hyoseo.dev

Context

The web app (ADR 0019) is a static SPA, so it needs static/CDN hosting, not an app server, and a deploy target separate from the FastAPI backend on DigitalOcean (ADR 0007). The maintainer owns hyoseo.dev with DNS on Cloudflare and runs a personal site there already.

Decision

  • Host the web app on Vercel, served at ww-extension.hyoseo.dev (subdomain of the existing hyoseo.dev). Chosen over Cloudflare Pages — the maintainer's default — deliberately, to gain familiarity with Vercel; either would serve a static SPA fine, so this is a low-stakes, reversible call.
  • DNS stays on Cloudflare: a CNAME for ww-extension points at Vercel, set DNS-only (grey cloud) so Cloudflare does not double-proxy Vercel's edge/TLS; Vercel issues the certificate.
  • Backend coordination required when the domain goes live:
    • FastAPI CORS allowlist includes https://ww-extension.hyoseo.dev (Bearer-token auth, no cookies → no credentialed-CORS handling needed). Decide per phase whether Vercel preview URLs are also allowed or only production.
    • Supabase Auth → Redirect URLs include the production domain (and preview URLs if previews must sign in); if Supabase uses the project's own Google OAuth credentials, the Google Cloud console authorized origins/redirects need the domain too.
    • Stripe success_url/cancel_url point at the domain for web-initiated checkout.
  • Only public values reach the SPA bundle: VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY (publishable, safe by design), and VITE_API_BASE_URL. No secret keys are ever shipped to the browser.

Consequences

  • + Push-to-deploy static hosting with free TLS and a custom subdomain; no server to operate for the frontend.
  • + Frontend and backend deploys are fully decoupled (different vendors, different triggers).
  • + A real success_url on the domain retires the chrome-extension:// Stripe result shim for web-initiated purchases.
  • − A third vendor in the stack (Vercel, alongside DO and Supabase) and a small DNS/redirect/CORS setup checklist that must be right before sign-in or payment works end-to-end.
  • − Vercel preview deployments get rotating URLs; if previews need auth or API access, CORS and Supabase redirects must account for them. Mitigation: treat previews as build-only and exercise auth/payment on production, or add a preview-wildcard allowance deliberately.
  • Reversible: moving to Cloudflare Pages (or DO static sites) later is a host swap behind the same subdomain, not a code change. Would supersede this ADR.
