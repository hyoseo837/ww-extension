ADR 0041 — Match criteria become facts + free text; weights and tiers retired

Context

The weighted-criteria schema (ADR 0013): five categories, each with a must / strong / nice-to-have weight and four value tiers. v8.4 simplified its vocabulary (ADR 0040) but kept the structure, and the owner rejected it (2026-06-10): rating categories by importance is an abstract question users can't naturally answer. Choosing among bucket-based, ranked, and facts-based models, the owner picked facts + free text.

Decision

  • match_criteria v2 — concrete facts only, no importance controls: work_authorization, locations[], work_modes[], target_term (single string), term_lengths[], languages[], wizard_completed_at. Same jsonb column; the new keys don't collide with v1's.
  • Importance lives in the user's own words. The existing preferences notes column is re-titled "In your own words, what matters most?" and becomes the sole carrier of emphasis, dealbreakers, and exclusions. The scoring prompt is rewritten to infer weight from phrasing ("non-negotiable" dominates; "would be nice" nudges) instead of from [must] annotations and a "never" tier.
  • Legacy v1 rows are converted at read time (server-side, where the profile row is loaded): each category's preferred values become the v2 fact list. Weights and the acceptable/avoid/excluded tiers are dropped — accepted loss; the user base is days old and tier data is effectively unset.
  • ADR 0013's schema and ADR 0040's tier-vocabulary decision are superseded; ADR 0040's wizard, gate, and wizard_completed_at decisions stand.

Consequences

  • The wizard and editor lose every importance/tier control — pure facts plus one text box. Nothing left to misunderstand.
  • Scoring explainability shifts to the LLM: how heavily something counts now depends on Gemini reading phrasing. The breakdown points in the response remain the audit trail. If inference proves unreliable, the structured-importance idea returns via a new ADR.
  • A hard-exclusion ("never") now reaches the scorer only through prose; the prompt's excluded gate keys on work-authorization conflicts and explicit user statements.
  • Read-time conversion means no SQL migration; v1 jsonb stays on disk until the user's next save overwrites it.

Alternatives considered

  • Three buckets (must / nice / never), item-level — recommended by the agent for keeping hard gates structured; owner preferred fewer controls and more trust in the LLM.
  • Ranked category priorities — category-level abstraction again; rejected.
  • Keep v1 with better labels — the v8.4 attempt; rejected by the owner.
