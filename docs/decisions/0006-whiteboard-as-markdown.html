ADR 0006 — Whiteboard as Markdown (exception to ADR 0001)

Context

ADR 0001 established HTML for all docs under docs/, with exceptions only for files tooling requires by name (CLAUDE.md, README.md at project root). The rationale was semantic structure and metadata.

A new doc was needed: a low-friction whiteboard for the user to jot raw ideas, possible changes, and future updates — entries that haven't earned a place in roadmap.html yet. Whiteboards work by being trivial to scribble on; any friction in the edit path discourages use, and an unused whiteboard is worse than no whiteboard.

HTML's ceremony (tags, attributes, restraint discipline) is precisely the wrong fit for fleeting captures. Markdown's looseness — bullets, headings, strikethrough — is the right fit. The semantic-metadata argument that justifies HTML for specs and ADRs does not apply to ephemeral notes that exist to be promoted out or deleted.

Decision

docs/whiteboard.md is Markdown. This is a deliberate exception to ADR 0001, joining CLAUDE.md and README.md as the small set of files where edit friction outweighs semantic structure.

No other doc under docs/ is permitted to be Markdown without a new ADR. The default remains HTML.

Consequences

  • + Whiteboard captures stay fast. The user can jot a thought in seconds without thinking about tags.
  • + Strikethrough (~~text~~) gives a one-keystroke way to mark dropped ideas without deleting the trail.
  • − Format inconsistency under docs/. Agents reading the tree must check extensions. Mitigated by this exception being narrow and documented.
  • − Whiteboard entries lack the <meta> status / date attributes that specs and ADRs use. Acceptable because whiteboard entries aren't queried — they're either promoted out or deleted.
  • − Opens a small precedent for "this doc should be Markdown too." Guarded by the explicit "no other doc may be Markdown without a new ADR" clause.
