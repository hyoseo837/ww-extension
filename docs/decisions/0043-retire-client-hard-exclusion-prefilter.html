ADR 0043 — Retire the client hard-exclusion pre-filter (supersedes ADR 0018)

Context

ADR 0018 added a credit-free client-side pre-filter: before scanning, the extension fetched the user's "never"-tier locations (match_criteria.preferred_locations.excluded) and marked matching rows Excluded without calling /scan. ADR 0041 (v8.5) replaced the weighted/tiered criteria with facts + free text — the v2 schema has no exclusion lists, and the accepted-lossy v1→v2 conversion drops them. Since the v8.5.7 launch the pre-filter's input key never exists, so the code path is unreachable: it silently no-ops on every scan, and its options-page toggle and getting-started FAQ claim ("skipped without spending a credit") describe behaviour that no longer happens.

Decision

Remove the dead path rather than re-key it. Deleted: the pre-filter fetch and gate in content.js (plus the City-column extraction that only fed it), the hardFilterEnabled toggle in options.html/options.js, and the FAQ claim (already dropped in v8.6.1). Exclusion still works — server-side: the scoring prompt's Excluded gate fires on work-authorization conflicts and explicit "never / won't / not willing to" statements in the user's own words, which covers ruled-out locations. The stale hardFilterEnabled key in users' chrome.storage.local is left behind harmlessly.

Consequences

  • Location exclusions now always cost a scan credit (the server scores and returns Excluded) instead of being skipped free. Acceptable: the v2 model has no structured exclusion list to match against, and the free skip was conservative/rarely-firing by design.
  • If a credit-free pre-filter is ever wanted again, it needs a machine-readable exclusion fact reintroduced into the v2 schema — a new ADR, not a revert of this one.
  • ADR 0018 is superseded; its roadmap/architecture mentions stay as history of the shipped v5 feature.
