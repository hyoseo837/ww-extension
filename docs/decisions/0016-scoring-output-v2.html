ADR 0016 — Scoring output v2: 1–100 score, server-derived 5-tier verdict, structured breakdown

Superseded by ADR 0017, which keeps this contract but changes the score scale from 1–100 to 1–20 (rescaling the band boundaries, same percentage cutoffs) and adds a sixth Excluded verdict for hard-criteria/eligibility gates. The breakdown, server-owned verdict, and clear-on-upgrade decisions below still hold.

Context

Through v5.1 the scorer returns { score: 1–10, verdict: Apply|Consider|Skip, reason }. The 1–10 scale is coarse (a "7" vs "8" carries little meaning), three verdicts collapse very different situations ("worth a look" and "borderline" both land in Consider), and the single prose reason gives the user no structured sense of which criteria or profile points moved the score. v5 thread #3 (spec v5.2.0) rewrites the prompt and the output to fix all three, now that the inputs are structured (criteria #1, profile #2).

The output shape is a contract across three surfaces — the Gemini response schema, the /scan API + stored scan.response, and the extension's badges / sidebar / score cache (ww_scores) — so it's a decision that constrains future work, not a per-phase detail.

Sub-decisions:

  1. Who owns the verdict. The model could emit the verdict directly, or the server could derive it from the score via fixed bands. Model-emitted risks the verdict and score disagreeing (a 90 labelled "Consider"); fixed bands keep them consistent but remove model nuance at the boundaries.
  2. How to express per-aspect reasoning. Keep prose only, or add a machine-readable breakdown the sidebar can render as discrete gain/loss points.
  3. What happens to scores already cached on the old 1–10 scale when the new scale ships.

Decision

The scoring output becomes:

{
  "score": 1–100,                  // model-produced
  "reason": "2–3 sentence summary", // model-produced
  "breakdown": [                   // model-produced; may be empty
    { "point": "prefers Toronto, job in Québec", "effect": "minus" },
    { "point": "Python + AWS match", "effect": "plus" }
  ],
  "verdict": "Strong Apply"        // SERVER-DERIVED from score (not from the model)
}
  • 1–100 score, model-produced. Finer resolution for ranking and band placement.
  • Server derives the verdict from fixed score bands — Strong Apply 85–100 · Apply 70–84 · Consider 50–69 · Unlikely 30–49 · Skip 1–29 — so score and verdict can never disagree and the ladder is one greppable source of truth. The model is told the bands (for calibration) but does not emit the verdict.
  • breakdown is a short array of { point, effect } (effect ∈ plus | minus) — the specific criteria / profile points that moved the score, rendered in the sidebar. reason stays as the prose summary alongside it.
  • Cached scores are cleared on upgrade. The client drops ww_scores / ww_posting_ids when its stored scoring-schema version changes, so badges never mix 1–10 and 1–100 values; postings re-score on the next scan.

Calibration in v5.2.0 is anchored only — band definitions, co-op framing, and worked anchors in the system prompt. Few-shot examples from real scored disagreements are a later tuning pass once enough live v5 scans accumulate; they don't change this contract.

Consequences

  • + Score and verdict are always consistent; the band ladder lives in one server-side function.
  • + The sidebar can show why a posting scored as it did, point by point — the core value of this phase.
  • + Finer 1–100 ranking improves sort order and the save-to-folder threshold.
  • − Breaking output change: the extension's badge / sidebar / sort / save-filter / load-validation and the ww_scores schema all change in lockstep, and old cached scores are discarded (a re-scan spends credits).
  • − Fixed bands mean a posting one point from a boundary flips verdict tier with no model say; acceptable given the consistency win, and the bands can be retuned in a later ADR.
  • − Replaying an old (pre-v5.2) successful scan_id returns the stored old-shape result (1–10, no breakdown). Harmless in practice — new scans use fresh ids — but noted.
