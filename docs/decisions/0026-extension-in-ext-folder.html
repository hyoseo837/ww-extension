ADR 0026 — Extension lives in its own ext/ folder

Context

The repo grew into a monorepo: the backend lives in server/ (ADR 0010) and the web app in web/ (ADR 0020). The Chrome extension, however, still lived implicitly at the repo root — manifest.json, src/, icons/, options.html, welcome.html sat alongside repo-level files (docs/, package.sh, dist/, CLAUDE.md, the two sibling folders).

That asymmetry made "the extension" the ill-defined leftover at the root rather than a named unit, and it collided with a plain src/ in web/ (two different src/ trees, only one of them at the top level). Collecting the extension into its own peer folder makes all three deployables symmetric and the Chrome load-unpacked target unambiguous.

Decision

  • Move the extension's source into ext/: manifest.json, src/, icons/, options.html, welcome.html, plus the extension's design mockups (design/) and Web Store listing assets (screenshots/). Chrome now loads ext/ as the unpacked extension.
  • Internal manifest paths are unchanged. manifest.json, src/, and icons/ move together, so the manifest's relative references (src/content.js, icons/icon16.png, …) still resolve — Chrome resolves them relative to the manifest's directory.
  • Release tooling stays at the repo root. package.sh and the dist/ output remain at the top level (repo-level release tooling, not per-folder build config). package.sh now cds into ext/ before zipping so the archive keeps manifest.json at its root, and writes the zip up to the root dist/.
  • The Web Store packaging allowlist (the boundary from ADR 0010 that keeps server/ and web/ out of the bundle) is unchanged in spirit — it now enumerates files under ext/.

This extends ADR 0010 / 0020 (it completes the monorepo layout) and does not supersede them — server/ and web/ are untouched.

Consequences

  • + Three symmetric peers (ext/, web/, server/); "the extension" is a named folder, not the root leftover. No more ambiguous top-level src/.
  • + The load-unpacked target is now exactly ext/ (previously the whole repo root, which also contained web/, server/, docs/ — loading it as an extension was always a slight abuse).
  • − The dev-load instruction changes (load ext/, not the repo root). CLAUDE.md, README.md, docs/architecture.html, and the dev-load memory are updated; archived docs and past per-phase specs keep their original root-relative paths as frozen history.
  • − package.sh can no longer zip from its own directory; it must cd ext first (one extra line). Failing to do so would store paths as ext/manifest.json inside the zip and break the install.
  • The vX.Y.Z version source moves to ext/manifest.json; the versioning rule (ADR 0002) is otherwise unchanged.
