ADR 0036 — Microsoft Entra (UWaterloo) sign-in, replacing Google

Context

Sign-in is a single OAuth provider, Google (Supabase), used by both the web app and the extension. New accounts get free signup credits — so anyone with a throwaway Gmail can farm free credits, the main abuse vector (only partly mitigated by the email-hash signup-bonus block, ADR 0029).

The product only serves UWaterloo students (the extension runs on WaterlooWorks). UWaterloo identities are Microsoft Entra ID (formerly Azure AD) — @uwaterloo.ca. A spike on 2026-06-05 confirmed feasibility: a multitenant Entra app authenticated an @uwaterloo.ca account through Supabase's "Azure" provider without hitting an admin-consent wall. The only gap was the email claim, fixed by adding the email optional claim to the app registration.

Decision

  • Switch the single OAuth provider from Google to Microsoft Entra (Supabase azure provider) — i.e. UWaterloo sign-in. Replace, not add: Google is disabled in Supabase. One account per real student is the anti-abuse goal, which "add alongside" would not achieve.
  • Tenant common (multitenant). Restricting to the uwaterloo.ca domain (reject other orgs / personal accounts by checking the email-domain / tenant claim) is desired but tracked as a follow-up — the spike used common.
  • Relies on the Entra email optional claim; if email is ever absent, fall back to preferred_username (the UPN, user@uwaterloo.ca).

Consequences

  • Existing Google users are not deleted — their auth.users rows, profiles, and credit balances persist — but they lose sign-in access. Their personal Gmail ≠ their @uwaterloo.ca email, so a UWaterloo login creates a new account (fresh bonus); old credits orphan. Accepted: the current user base is essentially test accounts — confirm there are no real paying users (Supabase → Users + the credit ledger) before flipping. Any that exist would need manual credit migration.
  • Alumni lose access once they leave UWaterloo. Accepted — it is a student tool.
  • Legal copy referencing "Google account / Google sign-in" (Privacy/Terms) must change to Microsoft/UWaterloo. Note: the separate references to Google's Gemini API (the scoring backend) stay — that is unrelated to sign-in.
  • Extension OAuth still uses launchWebAuthFlow with the chromiumapp.org redirect (ADR 0033) — unchanged; only the Supabase provider behind it changes. The Entra app's redirect is the Supabase callback (server-side), so the extension redirect allowlist is untouched.

Alternatives considered

  • Keep Google — status quo; abuse-prone.
  • Add Microsoft alongside Google — no migration pain, but Gmail-based credit farming continues, so it misses the point.
