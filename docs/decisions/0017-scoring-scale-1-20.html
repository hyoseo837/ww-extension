ADR 0017 — Scoring output v2.1: 1–20 score scale + Excluded verdict

Supersedes ADR 0016. Two revisions to ADR 0016's output contract, both decided during v5.2.0 implementation (spec v5.2.0) before any client release shipped on the 0016 shape: the score scale drops from 1–100 to 1–20, and a sixth verdict Excluded is added for hard-criteria/eligibility gates. Everything else from ADR 0016 carries over unchanged — model-produced reason, the structured breakdown of { point, effect }, the server-owned verdict, and clear-on-upgrade.

Context

Scale (1–100 → 1–20)

ADR 0016 set a 1–100 score. In practice 1–100 implies a precision the model can't deliver: the gap between a 73 and a 76 is noise, not signal, and a finer number invites the user to read meaning into gradations that aren't real. The signal that carries is the verdict tier; the number only needs enough resolution to rank and to place a posting within its tier. A 1–20 scale is honest about that while still giving ~4 gradations inside each tier.

The Excluded verdict

Under ADR 0016 a citizenship-blocked posting and a wrong-field posting both collapse into Skip at the bottom of the ladder, though they are qualitatively different: one is "cannot apply at all", the other is "could apply, weak fit." The prompt already tells the model to score eligibility-gate failures at the bottom, but nothing labels why a posting is there. A distinct verdict for hard-gate failures lets the user tell "ruled out" from "poor fit" at a glance, and is a cheap down-payment on the v5 hard-filter thread (#4) — though #4's pre-scan, credit-saving filter remains separate future work.

Decision

The score scale becomes 1–20 (model-produced). The verdict is server-derived from two inputs — the score and a model-emitted excluded boolean:

  • If excluded is true → verdict Excluded (regardless of score).
  • Otherwise, by fixed score band — same percentage cutoffs as ADR 0016, rescaled:
    Strong Apply
    17–20 (≥85%)
    Apply
    14–16 (≥70%)
    Consider
    10–13 (≥50%)
    Unlikely
    6–9 (≥30%)
    Skip
    1–5 (<30%)

excluded = true when the posting hits a hard no-go the candidate declared or legally fails: a work-authorization / citizenship / security-clearance requirement the candidate lacks, or any match-criterion value the candidate placed in their excluded tier (e.g. a location in their "never" tier, an excluded language). The model is instructed to set excluded and also score such a posting in the 1–5 range, so the low score and the Excluded label stay consistent — the model still owns a cause signal, never the verdict label itself.

The output shape:

{
  "score": 1–20,                   // model-produced (was 1–100)
  "reason": "2–3 sentence summary", // model-produced
  "breakdown": [                   // model-produced; may be empty
    { "point": "requires Canadian citizenship", "effect": "minus" },
    { "point": "Python + AWS match", "effect": "plus" }
  ],
  "excluded": false,               // model-produced; true on a hard gate
  "verdict": "Skip"                // SERVER-DERIVED from score + excluded
}

excluded stays server-side (it shapes the verdict and is stored on scan.response for faithful replay); the client receives only the resulting verdict string, so "Excluded" needs no extra client field. Sorting places Excluded below Skip. Cached scores are cleared on upgrade via the client's scoring-schema version, as in ADR 0016. Calibration stays anchored only this phase.

Consequences

  • + The scale matches the model's real resolution; the number stops implying false precision.
  • + "Ruled out" reads distinctly from "poor fit," the core ask — and the same percentage cutoffs mean ADR 0016's calibration intent and worked anchors carry straight over.
  • + The verdict is still server-owned and can't disagree with the score: the model emits a cause boolean, not the label, and excluded postings are pinned to the 1–5 range.
  • − The verdict is no longer a pure function of the score — it now also depends on excluded — so the "one greppable band function" from ADR 0016 grows one branch.
  • − Another breaking output change on top of ADR 0016, but absorbed by the same clear-on-upgrade mechanism (the scoring-schema version is already bumping this phase), and no client release shipped on 1–100, so there is no released scale to migrate.
  • − Any 1–100 rows the live backend (v5.2.1) already stored replay on that old scale, with no excluded field (→ defaults false). Harmless — new scans use fresh scan_ids — the same caveat ADR 0016 noted for pre-v5.2 replays.
