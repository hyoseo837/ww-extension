ADR 0023 — Tailwind CSS for the web app

Context

v6.1/v6.2 shipped the web app with a hand-rolled index.css baseline (warm tokens as CSS variables), explicitly deferred as placeholder styling until a real design pass. The user then designed the full v6 surface (account, billing, buy, profile, preferences, landing, sidebar, admin) in Google Stitch and exported it. The export is Tailwind: a custom theme config (the "Warm Editorial" palette — primary #8f4830 terracotta, Source Serif 4 + Inter, a 4px spacing scale, soft shadows) plus utility-class markup per screen.

Applying a Tailwind design to a hand-rolled-CSS app means translating every screen's utilities into semantic classes by hand — slow across eight screens and prone to drifting from the design. The project's minimal-code rule (ADR 0003) biases against a framework, but the same reasoning as the web-stack choice (ADR 0019) applies: the goal is a high-quality UI delivered fast, and the design source is already Tailwind.

Decision

  • Adopt Tailwind CSS (v3) in web/, with the Stitch theme config ported into tailwind.config.js (colors / fontFamily / fontSize / spacing / borderRadius) as the single token source. Plugins: @tailwindcss/forms and @tailwindcss/container-queries (as the export used).
  • JSX uses Tailwind utility classes, ported from the Stitch export per screen. This supersedes the hand-rolled index.css baseline from v6.1/v6.2 (which was always placeholder).
  • Fonts (Inter, Source Serif 4, Material Symbols) load via Google Fonts <link> in index.html, matching the export. Light mode only.
  • Tailwind v3 (JS config) over v4 (CSS @theme) specifically so the Stitch JS theme config ports near-verbatim.
  • Scope: the web app only. The extension keeps its hand-rolled sidebar.css; its later restyle will reuse the token values (palette/type) from this config, not necessarily Tailwind itself.

Consequences

  • + Each Stitch screen is a near-paste of its utilities — faithful to the design and fast to apply across all eight screens, with no per-screen translation drift.
  • + One authoritative token set (tailwind.config.js) for the whole web app; the extension sidebar can mirror the same values later.
  • − New build tooling (Tailwind + PostCSS) and a dep, a step away from ADR 0003 within the web app — judged worth it for the UI-quality goal, same trade as ADR 0019. Minimal-code still governs the React logic.
  • − Utility-class verbosity in JSX (long className strings). Accepted as the cost of design fidelity; shared patterns can be factored into small components.
  • − Two styling systems in the repo (Tailwind web, hand-rolled extension CSS) until/unless the extension is revisited.
  • The exported design's copy is not authoritative where it conflicts with the backend — e.g. the Buy screen's 1,500/5,000 "Save %" tiers are illustrative; the real packages (500/$5, 1000/$10, 2000/$20, strictly 1:1) stand. Apply the visual style, keep real data.
