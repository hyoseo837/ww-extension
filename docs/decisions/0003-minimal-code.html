ADR 0003 — Minimal code, no premature abstraction

Context

This is a solo-developed Chrome extension that grew from a scoring loop into a polished tool over three major versions. AI coding agents producing code for this project default to adding abstractions, error-handling layers, and configuration plumbing that anticipate hypothetical future needs. For a single-developer browser extension, this overhead is pure cost — it complicates the code, makes refactors harder, and pollutes agent context windows on subsequent reads.

Decision

Write the simplest, clearest, most direct code that solves the problem at hand. No abstractions beyond what the task requires. No clever patterns, no premature generalization. Three similar lines are better than a premature abstraction.

No error handling, fallbacks, or validation for scenarios that can't happen. Trust internal code and framework guarantees. Only validate at system boundaries (user input, external APIs, the WW page DOM).

Default to no comments. Add a comment only when the why is non-obvious — a workaround, a subtle invariant, a hidden constraint. Don't explain what the code does; the code does that.

Consequences

  • + Code stays readable end-to-end without jumping through abstraction layers.
  • + Smaller agent context windows per file read — directly improves agent productivity.
  • + Refactors are easier because there is less inherited indirection to preserve.
  • − When duplication does eventually warrant extraction, the work to extract is borne later rather than spread across initial writes. Acceptable for a project at this scale.
  • − Agents asked to "improve" code without a specific bug or feature target will be tempted to add structure. The rule must be enforced via rules.html and code review.
