ADR 0034 — Bonus-credit packages + re-margin to ~1 credit/scan

Context

ADR 0012 set the credit economy: 1 credit = $0.01 CAD, per-scan cost derived from Gemini token usage via a single MARGIN dial (billing/pricing.py), and Stripe packages where cad_cents == credits (no bonus). At MARGIN = 5.0 a Flash scan runs ~0.5 credits, so the 100-credit signup bonus buys ~200 scans and the packs were 500 / 1000 / 2000 credits at $5 / $10 / $20.

The owner wants a simpler, more marketable story: a scan costs about 1 credit, the entry price is $1 for 100 credits, and bigger packs include bonus credits. Token-based pricing stays (it keeps cost honest and the refund-on-actual machinery intact); only the dial and the package table change.

Decision

  • Keep token-based per-scan pricing and the base unit 1 credit = $0.01 CAD. No change to the scan/extract debit-estimate-settle flow. PDF extract stays variable (token-based) — only the dial moves.
  • Re-margin: MARGIN 5.0 → 10.0 so a Flash scan costs ~1 credit and the 100-credit signup bonus buys ~100 scans. One number, as the pricing module intends.
  • Bonus-credit packages (this is the part that amends ADR 0012 — cad_cents no longer equals credits):
    idprice (cad_cents)creditsbonus
    credits_100$1 (100)100—
    credits_550$5 (500)550+50
    credits_1200$10 (1000)1200+200
    Stripe is charged cad_cents; the ledger is granted credits — already how create_checkout_session / grant_purchase work, so the bonus needs no new code, only the table values. The line-item name f"{credits} credits" stays correct.

Consequences

  • Retires ADR 0012's cad_cents == credits invariant; the code comments asserting it are updated. Server (billing/payments.py) and web (web/src/packages.ts) package tables must stay in lockstep — changed together in one commit.
  • Existing balances buy ~half as many scans as before the re-margin (0.5 → ~1 credit/scan). Accepted: the user base is tiny (post-launch) and the bonus packs offset it.
  • Margin headroom is fine — a Flash scan's raw Google cost is ~$0.001; at $0.01–$0.0083 per credit revenue the multiple stays ample even on the bonus tiers.
  • Web pricing copy moves from "1 credit = $0.01 CAD" to "about 1 credit per scan, bigger packs include bonus credits."
  • No Stripe dashboard change (prices are inline price_data, ADR 0012). Server change → server/pyproject.toml bump (ADR 0010).
