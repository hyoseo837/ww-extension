ADR 0009 — Backend stack: FastAPI on Python

Context

The backend serves a small JSON API: auth handoff (verify Supabase JWT, return /me), /scan (forward posting payload to Gemini, debit credit, return score), credit-balance reads, and Stripe webhooks. No long-running background jobs in v4 scope.

Stack candidates: FastAPI (Python), Express or Hono (Node), Django REST Framework (Python), chi or Echo (Go). The user named FastAPI on Python; this ADR records the choice and captures why no alternative was pursued.

Decision

The backend is a single FastAPI application on Python 3.12+, packaged as a Docker image and deployed to DigitalOcean App Platform (see ADR 0007). The repo follows a feature-grouped layout (auth/, scoring/, billing/, core/) rather than a layer-grouped one.

Consequences

  • + Pydantic schemas validate request/response payloads at the boundary and auto-generate an OpenAPI spec that drives this repo's docs/reference/api.html mirror.
  • + Aligns with the user's existing Python proficiency — no new language to learn alongside Supabase, Stripe, and DO App Platform.
  • + Async I/O suits the call pattern (Gemini + Supabase + Stripe are all network-bound).
  • + Feature-grouped layout keeps each feature self-contained (router + schemas + service + models in one folder) — easier to find code, easier to extract a feature later.
  • − Python is slower per dollar of compute than Go or Bun-on-Hono. Not a concern at v4's expected scale.
  • − Python deploys are heavier than Hono/Bun for cold-start scenarios. Moot on DO App Platform (persistent process, no cold starts).
