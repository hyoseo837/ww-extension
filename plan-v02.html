ww-extension — v02 Project Plan

Where v01 ended

v01 (commits v01.001 through v01.020) shipped the working core: scan all jobs via selectAll, fetch each posting overview via a page-bridge, score against a pasted CV with Gemini, render badges inline in the table and a ranked sidebar, persist scores across reloads, click-to-navigate to any job's row with cross-page support, per-job and bulk Save-to-Folder, score-and-verdict filtering on bulk save, full polish on errors / empty states / loading overlay flicker. The user designated v01.020 as "first complete version."

v01 documents (plan.html, impl.html, history.html) are kept as historical reference and should not be extended. All new work is documented in this file and its siblings impl-v02.html / history-v02.html.

v02 Vision

v01 proved the workflow but the candidate context is weak: it's a single hand-typed textarea. v02 raises the quality of that context (PDF upload + AI extraction, soft preferences) so scoring decisions are sharper. Further v02 features are TBD and will be added here as the user confirms them.

Confirmed v02 features (in implementation order)

All three phases below are designed to be small and independently committable. Each leaves the extension in a fully working state so a session that runs out of context mid-feature can resume cleanly at the next phase. Full design notes for every phase live in ~/.claude/plans/tidy-orbiting-nova.md — read that before implementing.

v02.001 — Options page replaces popup

The browser-action popup disappears when the user clicks anywhere outside it, which the user finds repeatedly frustrating. v02.001 removes the popup entirely and replaces it with an Options page that opens in a real browser tab. The toolbar icon opens it; a new ⚙ Settings button in the WW sidebar header also opens it.

This phase is a pure UI migration with no behavior changes — all existing settings (apiKey, model, cvText) work identically, and the v01 Scan All Jobs flow is untouched. It must come first because the next two phases need more vertical real estate than the 320px popup affords.

v02.002 — Profile from PDF

WaterlooWorks lets students export a combined PDF containing résumé, grade report, and co-op work history. The Options page accepts that single PDF, sends it to Gemini's multimodal endpoint with an "extract as plain text" prompt, and populates the existing cvText textarea with the result. The textarea remains the source of truth — the user can clean it up before saving, or skip the upload entirely and type from scratch.

v02.003 — Preferences field

A free-form soft-constraints textarea ("prefer Waterloo, Toronto OK, no San Francisco; backend or data roles only"). Stored separately and included in the Gemini scoring prompt as its own labelled section, omitted entirely when empty so users who don't fill it pay no token cost.

v02.004 — Context caching + responseSchema

v02.002 will make the per-call profile large (inline PDF = 5,000–20,000+ tokens). Without intervention a 200-job scan after v02.002 would cost 10–40× what it costs today. v02.004 fixes this in two moves:

  • responseSchema — replace the "respond as JSON…" prose in the prompt with Gemini's native structured-output config. Saves ~50 tokens/call and eliminates JSON parse failures.
  • Context caching — upload the stable portion (system instruction + profile) once per scan session via POST /v1beta/cachedContents. Each subsequent scoring call references the cache name; cached tokens are billed at ~25% of normal input rate. Job descriptions and preferences (small, variable) are always sent inline.

Caching must come after v02.002 because Gemini 2.5 Flash has a 1,024-token minimum for cached content — the text CV alone (~550 tokens) is below the floor; the PDF profile easily clears it. Cache lifetime is per scan session (TTL 30 min), not persisted to chrome.storage.

Batching multiple jobs per request was considered and rejected: it achieves the same token savings as caching but at the cost of relative-scoring bias and worse per-job error recovery.

Out of scope (still)

Same as v01: auto-apply, cover-letter generation, non-Gemini providers, backend server, mobile/desktop apps. Cross-session score persistence is now in scope (already shipped in v01).
