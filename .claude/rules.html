Project Rules

All agents working on this project must follow these rules strictly.

1. HTML for all documents

Use HTML for all plans, documents, and written artifacts — not markdown. HTML files must contain only content and metadata. No CSS, no JavaScript, no design elements. HTML is used because it supports richer semantic metadata than markdown.

2. Read the right doc set

The project has two doc generations. Always read the current set first:

  • Current (v02, since 2026-05-20): plan-v02.html, impl-v02.html, history-v02.html. All new work documents itself here.
  • Archived (v01.001 → v01.020): plan.html, impl.html, history.html. Historical reference only. Do not extend.

Both the v01 plan and the v02 plan are user-confirmed. Treat their contents as decided. Build directly from them; if something is not covered, confirm with the user.

3. Minimal code

Write the simplest, clearest, most direct code that solves the problem. No abstractions beyond what the task requires. No clever patterns, no premature generalization. Three similar lines is better than a premature abstraction.

4. Document in history.html after each phase

After completing each implementation phase, add a concise entry to history.html. Record only crucial decisions or non-obvious choices — not a step-by-step log. A decision is worth recording if a future agent reading only history.html and plan.html would otherwise make a different choice.

5. Versioning — vXX.XXX

Every commit must include a version number in the message using the format vXX.XXX. The first number is the major version — increment it when adding a new feature or reconstructing the project structure. The second number increments on every commit. Some versions may be non-functional; that is expected and acceptable.
