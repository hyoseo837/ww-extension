Project Rules

All agents working on this project must follow these rules strictly.

1. HTML for all documents

Use HTML for all plans, documents, and written artifacts — not markdown. HTML files must contain only content and metadata. No CSS, no JavaScript, no design elements. HTML is used because it supports richer semantic metadata than markdown.

2. Read the right doc set

The project has two doc generations. Always read the current set first:

  • Current (v02, since 2026-05-20): docs/plan.html, docs/impl.html, docs/history.html. All new work documents itself here.
  • Archived (v01.001 → v01.020): docs/v01-archive/plan.html, docs/v01-archive/impl.html, docs/v01-archive/history.html. Historical reference only. Do not extend.

Both the v01 plan and the v02 plan are user-confirmed. Treat their contents as decided. Build directly from them; if something is not covered, confirm with the user.

3. Minimal code

Write the simplest, clearest, most direct code that solves the problem. No abstractions beyond what the task requires. No clever patterns, no premature generalization. Three similar lines is better than a premature abstraction.

4. Document in docs/history.html after each phase

After completing each implementation phase, add a concise entry to docs/history.html. Record only crucial decisions or non-obvious choices — not a step-by-step log. A decision is worth recording if a future agent reading only docs/history.html and docs/plan.html would otherwise make a different choice.

5. Versioning — vXX.YZW

Every commit must include a version number in the message using the format vXX.YZW (three digits after the dot). The three parts decompose as:

  • XX — major version. Increment when adding a new feature set or restructuring the project.
  • YZ — planned phase within the major version. Each phase's first commit ends in 0 (e.g. v03.010, v03.020, v03.030).
  • W — sub-commit within a phase. If a phase needs more than one commit, increment the last digit (v03.020 → v03.021 → v03.022). The next planned phase resets to 0 (e.g. v03.030).

Some versions may be non-functional; that is expected and acceptable.

manifest.json mirrors the commit version, translated to the three-component form Chrome requires: vXX.YZW → XX.YZ.W. Examples: v03.010 → 3.1.0, v03.020 → 3.2.0, v03.022 → 3.2.2. Bump manifest.json's version field in the same commit that introduces the new version number.
